Today's focus: **Crons — securing your Vercel cron endpoint**

Vercel sends a `Authorization: Bearer <secret>` header with every cron invocation. Here's how to verify it:

```ts
// app/api/cron/heartbeat/route.ts
import { NextRequest, NextResponse } from "next/server";

export async function GET(req: NextRequest) {
  const authHeader = req.headers.get("authorization");
  if (authHeader !== `Bearer ${process.env.CRON_SECRET}`) {
    return NextResponse.json({ error: "Unauthorized" }, { status: 401 });
  }

  // ... rest of your existing handler
}
```

**Setup:** Add `CRON_SECRET` to your Vercel environment variables — set it to any random string (e.g. `openssl rand -hex 32`). Vercel injects it automatically on cron runs. For local testing, add it to `.env.local`.

**Why this matters:** Cron endpoints are plain HTTP routes. Without auth, anyone who finds the URL can fire your cron on demand — running arbitrary side effects (database writes, emails, deploys) outside of schedule. The `CRON_SECRET` check is the standard Vercel-recommended pattern and costs two lines of code.

**Bonus:** Once you add this, your heartbeat will also accurately reflect whether the app is *reachable from outside* (since the cron call comes from Vercel's infrastructure, not from within your app). That makes the heartbeat a true external health check rather than a self-ping.
