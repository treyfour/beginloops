**Add HMAC-SHA256 signature verification to `app/api/webhooks/route.ts` using Node's built-in `crypto` module.**

Today's focus: **Webhooks — securing your endpoint so only trusted senders can trigger it**

This has come up twice before. Here is the exact implementation:

```ts
// app/api/webhooks/route.ts
import { createHmac, timingSafeEqual } from "crypto";
import { NextRequest, NextResponse } from "next/server";

export async function POST(req: NextRequest) {
  const body = await req.text(); // read raw bytes before parsing
  const sig = req.headers.get("x-hub-signature-256") ?? "";
  const secret = process.env.GITHUB_WEBHOOK_SECRET ?? "";

  const expected =
    "sha256=" + createHmac("sha256", secret).update(body).digest("hex");

  // timingSafeEqual prevents timing-based signature leaks
  if (
    sig.length !== expected.length ||
    !timingSafeEqual(Buffer.from(sig), Buffer.from(expected))
  ) {
    return NextResponse.json({ error: "Invalid signature" }, { status: 401 });
  }

  const payload = JSON.parse(body);
  console.log("Verified push event:", payload.repository?.full_name);
  return NextResponse.json({ ok: true });
}
```

Add `GITHUB_WEBHOOK_SECRET` to your `.env.local` and to your Vercel environment variables. GitHub will send this value in every webhook request as the `x-hub-signature-256` header.

**Why `timingSafeEqual`?** A plain `===` comparison leaks timing information — an attacker can guess the correct signature one character at a time by measuring how long the comparison takes before it returns `false`. `timingSafeEqual` always runs in constant time regardless of where the mismatch occurs. This is a small change that closes a real attack vector.
