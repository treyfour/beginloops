Today's focus: **Heartbeats — decoupling "run the check" from "read the status"**

The heartbeat at `/api/cron/heartbeat` currently runs all its checks on every request. In production, you'd never want every page load to fan out to sub-system checks — instead the cron runs the check and stores the result, and a lightweight `/status` endpoint just returns the last cached value.

**Step 1 — Add a module-level cache to the heartbeat route** (`app/api/cron/heartbeat/route.ts`):

```ts
// Module-level variable — lives for the lifetime of the serverless instance
let lastResult: { status: string; timestamp: string; checks: object } | null = null;

export async function GET() {
  // ... existing check logic ...

  const payload = {
    status: webhookStatus === "ok" ? "ok" : "degraded",
    timestamp: new Date().toISOString(),
    checks: { webhookEndpoint: webhookStatus },
  };

  lastResult = payload; // cache it
  console.log("[heartbeat]", JSON.stringify(payload));
  return NextResponse.json(payload);
}

// Export so /api/status can read it
export function getLastResult() {
  return lastResult;
}
```

**Step 2 — Create `app/api/status/route.ts`:**

```ts
import { NextResponse } from "next/server";
import { getLastResult } from "../cron/heartbeat/route";

export async function GET() {
  const last = getLastResult();
  if (!last) {
    return NextResponse.json(
      { status: "unknown", message: "No heartbeat run yet" },
      { status: 503 }
    );
  }
  return NextResponse.json(last);
}
```

**Why this matters:** This is the canonical heartbeat architecture — the *check* (expensive, runs on a cron) is separated from the *read* (cheap, serves a cached snapshot). Real uptime dashboards, status pages, and health-check systems all work this way: cron writes, UI reads. Once you build this, updating the `useHeartbeat` hook to poll `/api/status` instead of `/api/cron/heartbeat` directly makes the whole system correct: the UI never accidentally triggers expensive checks just by rendering.
