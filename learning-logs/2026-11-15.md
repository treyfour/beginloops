**Guard your Vercel cron endpoint with `CRON_SECRET` — without it, anyone can hit `/api/cron/heartbeat` on demand, burning your usage and masking real failures.**

Today's focus: **Crons — protecting who can trigger them**

Vercel automatically injects an `Authorization: Bearer <CRON_SECRET>` header on every cron invocation. Add this check to `app/api/cron/heartbeat/route.ts`:

```ts
import { NextRequest, NextResponse } from "next/server";

export async function GET(req: NextRequest) {
  const authHeader = req.headers.get("authorization");
  if (authHeader !== `Bearer ${process.env.CRON_SECRET}`) {
    return NextResponse.json({ error: "unauthorized" }, { status: 401 });
  }

  // ... rest of heartbeat logic unchanged
}
```

Then in Vercel → Settings → Environment Variables, add `CRON_SECRET` with a random value (use `openssl rand -hex 32` to generate one). Vercel will inject that same value into the header on every scheduled run — your endpoint rejects anything that doesn't match.

**Why this matters:** Cron endpoints are public GET routes. Without a secret, any script can call them in a loop, trigger false `"degraded"` alerts, or consume your Vercel function quota. The `CRON_SECRET` pattern is the idiomatic Vercel solution — it's cheap to add and pairs well with the HMAC signature check you'll eventually add to the webhook handler.
