Today's focus: **Webhooks — verifying that an incoming request is genuinely from GitHub**

Right now `/api/webhooks` accepts any POST request. GitHub signs every payload with a secret you share — it sends an `x-hub-signature-256` header containing `sha256=<hmac>`. Without checking that header, anyone can forge a fake push event and trick your handler into running.

**Step 1 — Create the secret.** In your GitHub repo → Settings → Webhooks, set a "Secret" value (a long random string). Add the same value to Vercel as `WEBHOOK_SECRET`, and to `.env.local` for local dev.

**Step 2 — Add a `verifySignature` helper and guard at the top of the POST handler:**

```ts
import { NextRequest, NextResponse } from "next/server";
import { createHmac, timingSafeEqual } from "crypto";

async function verifySignature(req: NextRequest, rawBody: Buffer): Promise<boolean> {
  const sig = req.headers.get("x-hub-signature-256");
  if (!sig || !process.env.WEBHOOK_SECRET) return false;

  const expected = "sha256=" + createHmac("sha256", process.env.WEBHOOK_SECRET)
    .update(rawBody)
    .digest("hex");

  return timingSafeEqual(Buffer.from(sig), Buffer.from(expected));
}

export async function POST(req: NextRequest) {
  const rawBody = Buffer.from(await req.arrayBuffer());

  if (!(await verifySignature(req, rawBody))) {
    return NextResponse.json({ error: "invalid signature" }, { status: 401 });
```

**Why this matters:** Without signature verification, your webhook is an unauthenticated trigger anyone can hit — they can forge push events, flood your logs, or trigger any side effects your handler performs. `timingSafeEqual` is critical here: a plain string compare leaks timing information that lets attackers brute-force the secret one byte at a time. This is the standard pattern GitHub's own docs recommend, and it pairs directly with the `CRON_SECRET` guard (yesterday's suggestion) to lock down both inbound routes in the app.
