Today's focus: **Crons (authorization — protecting the cron endpoint)**

Your heartbeat route is currently open to the internet — anyone who discovers `GET /api/cron/heartbeat` can trigger it, drain your function quota, or spam your logs. Vercel Crons solves this by sending a secret header with every scheduled invocation. Checking that header is the standard pattern for locking down cron routes.

**Step 1 — Add the secret to `.env.local`:**

```
CRON_SECRET=a-long-random-string-you-choose
```

Add the same value to your Vercel project → Settings → Environment Variables (production + preview).

**Step 2 — Check the `Authorization` header in the route:**

```ts
// app/api/cron/heartbeat/route.ts
import { NextRequest, NextResponse } from "next/server";

export async function GET(req: NextRequest) {
  // Vercel sends: Authorization: Bearer <CRON_SECRET>
  const authHeader = req.headers.get("authorization");
  const expectedToken = process.env.CRON_SECRET;

  if (!expectedToken || authHeader !== `Bearer ${expectedToken}`) {
    console.warn("[heartbeat] rejected — missing or invalid CRON_SECRET");
    return NextResponse.json({ error: "Unauthorized" }, { status: 401 });
  }

  // ... rest of your existing handler unchanged
  const base = process.env.VERCEL_URL
    ? `https://${process.env.VERCEL_URL}`
    : "http://localhost:3000";

  let webhookStatus: "ok" | "unreachable" = "unreachable";
  try {
    const res = await fetch(`${base}/api/webhooks`, {
      method: "POST",
      headers: { "Content-Type": "application/json", "x-github-event": "ping" },
      body: JSON.stringify({ zen: "heartbeat probe" }),
    });
    webhookStatus = res.ok ? "ok" : "unreachable";
  } catch {
    webhookStatus = "unreachable";
  }

  const payload = {
    status: webhookStatus === "ok" ? "ok" : "degraded",
    timestamp: new Date().toISOString(),
    checks: { webhookEndpoint: webhookStatus },
  };

  console.log("[heartbeat]", JSON.stringify(payload));
  return NextResponse.json(payload);
}
```

**Step 3 — Register the schedule in `vercel.json`** (so Vercel actually calls this route on a timer):

```json
{
  "crons": [
    {
      "path": "/api/cron/heartbeat",
      "schedule": "*/5 * * * *"
    }
  ]
}
```

`*/5 * * * *` = every 5 minutes. Vercel will send the `Authorization: Bearer <CRON_SECRET>` header automatically.

**Three concepts to internalize:**

1. **Why a shared secret instead of IP allowlisting?** Vercel doesn't publish a stable list of cron IPs. A secret header is simpler, portable, and the pattern Vercel officially recommends. Keep it long (32+ chars), random, and out of source control.

2. **The `Authorization: Bearer` format:** This is the standard HTTP convention for bearer tokens. Your check must be an exact string match: `Bearer ` + the secret. Any whitespace difference or missing prefix → reject.

3. **Cron expressions:** `*/5 * * * *` means "every 5 minutes". The five fields are minute, hour, day-of-month, month, day-of-week. Vercel Crons supports only minute-level granularity (not seconds). A heartbeat every 5 minutes is a reasonable interval — frequent enough to detect downtime quickly, infrequent enough to stay within Vercel's free-tier cron limits.
