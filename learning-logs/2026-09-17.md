Today's focus: **Heartbeats — from single probe to time-series history**

The current heartbeat probe returns live status each time it's called but remembers nothing. Adding a simple in-memory history teaches you a key serverless lesson: module-level variables persist between warm invocations but reset on cold starts. That constraint is worth discovering now, before you reach for a database.

Update `app/api/cron/heartbeat/route.ts`:

```ts
import { NextResponse } from "next/server";

interface HeartbeatResult {
  status: "ok" | "degraded";
  timestamp: string;
  checks: { webhookEndpoint: "ok" | "unreachable" };
}

// Survives across warm invocations; resets on cold starts
const history: HeartbeatResult[] = [];
const MAX_HISTORY = 10;

export async function GET() {
  const base = process.env.VERCEL_URL
    ? `https://${process.env.VERCEL_URL}`
    : "http://localhost:3000";

  let webhookStatus: "ok" | "unreachable" = "unreachable";
  try {
    const res = await fetch(`${base}/api/webhooks`, {
      method: "POST",
      headers: { "Content-Type": "application/json", "x-github-event": "ping" },
      body: JSON.stringify({ zen: "heartbeat probe" }),
    });
    webhookStatus = res.ok ? "ok" : "unreachable";
  } catch {
    webhookStatus = "unreachable";
  }

  const result: HeartbeatResult = {
    status: webhookStatus === "ok" ? "ok" : "degraded",
    timestamp: new Date().toISOString(),
    checks: { webhookEndpoint: webhookStatus },
  };

  history.push(result);
  if (history.length > MAX_HISTORY) history.shift();

  console.log("[heartbeat]", JSON.stringify(result));
  return NextResponse.json(result);
}

export async function POST() {
  // Return the stored history so you can inspect it
  return NextResponse.json({ history, count: history.length });
}
```

**Why this matters:** Every monitoring system needs a window of past results, not just the current state. You're learning the cheapest possible version — module memory — which reveals the fundamental challenge of stateless serverless: the history resets whenever the function cold-starts. Once that limitation bites you (it will), you'll understand exactly why Vercel KV, Redis, or a database exists. Learning the limitation is the lesson.
