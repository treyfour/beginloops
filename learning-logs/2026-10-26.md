Today's focus: **Crons — securing scheduled route handlers**

Cron routes run on a schedule, but their URLs are publicly reachable HTTP endpoints. Without a secret check, anyone can POST to them and trigger your scheduled logic at will. Vercel Cron automatically sends an `Authorization: Bearer <CRON_SECRET>` header with every invocation — you just need to verify it.

```ts
// app/api/cron/heartbeat/route.ts  (add this guard at the top of the handler)
import { NextRequest, NextResponse } from "next/server";

const CRON_SECRET = process.env.CRON_SECRET ?? "";

export async function GET(req: NextRequest) {
  const authHeader = req.headers.get("authorization");

  if (authHeader !== `Bearer ${CRON_SECRET}`) {
    return NextResponse.json({ error: "Unauthorized" }, { status: 401 });
  }

  // ... rest of your heartbeat logic
  console.log("Heartbeat triggered at", new Date().toISOString());
  return NextResponse.json({ ok: true, ts: Date.now() });
}
```

Then add to `vercel.json`:
```json
{
  "crons": [
    {
      "path": "/api/cron/heartbeat",
      "schedule": "*/5 * * * *"
    }
  ]
}
```

And set `CRON_SECRET` in your Vercel project environment variables (Settings → Environment Variables). Vercel will inject it automatically into every cron invocation.

The key insight: **a cron job is just an HTTP route called on a schedule.** Protecting it is the same pattern as protecting any other API route — a shared secret in a header that only the caller knows.
