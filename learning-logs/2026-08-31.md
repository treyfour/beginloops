**Step 1 — add an in-memory log to your webhook route (`app/api/webhooks/route.ts`):**

```ts
// At the top of the file, outside any function — module-level state persists for the
// lifetime of the serverless function instance (a few minutes between requests).
const MAX_EVENTS = 20;
export const webhookLog: Array<{ id: string; ts: string; payload: unknown }> = [];

export async function POST(req: Request) {
  const payload = await req.json();
  webhookLog.unshift({
    id: crypto.randomUUID(),
    ts: new Date().toISOString(),
    payload,
  });
  if (webhookLog.length > MAX_EVENTS) webhookLog.length = MAX_EVENTS;
  console.log("[webhook] received", payload);
  return Response.json({ ok: true });
}
```

**Step 3 — create `app/hooks/useWebhookEvents.ts`:**

```ts
"use client";

import { useState, useEffect, useCallback } from "react";

interface WebhookEvent {
  id: string;
  ts: string;
  payload: unknown;
}

export function useWebhookEvents(intervalMs = 5_000) {
  const [events, setEvents] = useState<WebhookEvent[]>([]);
  const [loading, setLoading] = useState(true);

  const poll = useCallback(async () => {
    try {
      const res = await fetch("/api/webhooks/log");
      if (!res.ok) throw new Error(`HTTP ${res.status}`);
      const { events } = await res.json();
      setEvents(events);
    } catch (err) {
      console.error("[useWebhookEvents] poll failed", err);
    } finally {
      setLoading(false);
    }
  }, []);

  useEffect(() => {
    poll();
    const id = setInterval(poll, intervalMs);
    return () => clearInterval(id);
  }, [poll, intervalMs]);

  return { events, loading };
}
```

**Three concepts to lock in:**

1. **Module-level state in serverless functions** — `webhookLog` lives at the top level of `route.ts`, outside any function. Node.js caches modules, so this array persists across requests *within the same function instance*. In production on Vercel, instances spin down and memory resets — which is why real apps use a database (Redis, Postgres). This pattern is perfect for learning; in production you'd swap `webhookLog` for a `ZADD`/`ZRANGE` call to Redis.

2. **Why a separate `/log` route rather than a socket?** WebSockets/SSE are powerful but complex to set up in Next.js App Router. A polled GET endpoint achieves 80% of the experience with 20% of the complexity — you can always upgrade to SSE later once the data model is solid.

3. **The `useCallback` + `useEffect` pattern** — this is the canonical React pattern for stable async side effects. `useCallback` ensures `poll` doesn't change identity on re-renders, which keeps `useEffect` from tearing down and re-creating the interval unnecessarily. You saw this in `useHeartbeat` yesterday — repetition is intentional.
