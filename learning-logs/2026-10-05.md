Today's focus: **Webhooks — proving the request actually came from GitHub**

Right now, *anyone* who discovers your webhook URL can POST a fake event and your handler will process it. GitHub prevents this by signing every payload with your webhook secret using HMAC-SHA256 and sending the result in the `X-Hub-Signature-256` header. Verifying that signature is the single most important thing you can add to a webhook handler.

Add a helper and call it at the top of your `POST` handler:

```ts
import { NextRequest, NextResponse } from "next/server";
import { createHmac, timingSafeEqual } from "crypto";

async function verifyGitHubSignature(
  req: NextRequest,
  rawBody: string
): Promise<boolean> {
  const secret = process.env.GITHUB_WEBHOOK_SECRET;
  if (!secret) return true; // skip in local dev if secret not set

  const sig = req.headers.get("x-hub-signature-256");
  if (!sig) return false;

  const expected = "sha256=" + createHmac("sha256", secret).update(rawBody).digest("hex");
  // timingSafeEqual prevents timing attacks that could leak the secret
  return timingSafeEqual(Buffer.from(sig), Buffer.from(expected));
}

export async function POST(req: NextRequest) {
  const rawBody = await req.text(); // read as text first so we can hash it
  const body = JSON.parse(rawBody);

  const valid = await verifyGitHubSignature(req, rawBody);
  if (!valid) {
    return NextResponse.json({ error: "Invalid signature" }, { status: 401 });
  }

  const event = req.headers.get("x-github-event") ?? "unknown";
  // ... rest of your handler unchanged
}
```

Set `GITHUB_WEBHOOK_SECRET` in Vercel → Settings → Environment Variables, and paste the same value into your GitHub repo's webhook settings (Settings → Webhooks → Secret).

**Why this matters:**
- HMAC-SHA256 proves the payload wasn't tampered with and originated from GitHub — not just that someone has the URL.
- `timingSafeEqual` is a non-obvious but critical detail: a naïve string comparison (`===`) leaks timing information that could let an attacker brute-force your secret one character at a time.
- You'll use the exact same pattern for Stripe webhooks, Linear webhooks, and any other service that signs its payloads — it's the universal webhook security primitive.
- Once you understand this, the cron `Authorization: Bearer` check from yesterday and HMAC here are two faces of the same idea: every external caller must prove who it is before your code runs.
