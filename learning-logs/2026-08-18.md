Today's focus: **Heartbeats (making your health check actually trustworthy)**

Your heartbeat route already fires a probe against the webhook endpoint — great. But right now anyone can call it, and you have no idea how long the probe took. Both of those are real problems in production:

1. Without auth, a bad actor can spam your heartbeat to inflate costs or gather timing data.
2. Without latency, you can't tell the difference between "slow but alive" and "fast and healthy."

Here's the upgraded route:

```ts
// app/api/cron/heartbeat/route.ts
import { NextRequest, NextResponse } from "next/server";

export async function GET(req: NextRequest) {
  // 1. Auth — Vercel Cron sets this header automatically when CRON_SECRET is set
  const cronSecret = process.env.CRON_SECRET;
  if (cronSecret) {
    const auth = req.headers.get("authorization");
    if (auth !== `Bearer ${cronSecret}`) {
      return NextResponse.json({ error: "Unauthorized" }, { status: 401 });
    }
  }

  const base = process.env.VERCEL_URL
    ? `https://${process.env.VERCEL_URL}`
    : "http://localhost:3000";

  // 2. Latency — record start/end around the probe
  let webhookStatus: "ok" | "unreachable" = "unreachable";
  let durationMs: number | null = null;
  const start = Date.now();

  try {
    const res = await fetch(`${base}/api/webhooks`, {
      method: "POST",
      headers: { "Content-Type": "application/json", "x-github-event": "ping" },
      body: JSON.stringify({ zen: "heartbeat probe" }),
    });
    durationMs = Date.now() - start;
    webhookStatus = res.ok ? "ok" : "unreachable";
  } catch {
    durationMs = Date.now() - start;
    webhookStatus = "unreachable";
  }

  const payload = {
    status: webhookStatus === "ok" ? "ok" : "degraded",
    timestamp: new Date().toISOString(),
    durationMs,
    checks: { webhookEndpoint: webhookStatus },
  };

  console.log("[heartbeat]", JSON.stringify(payload));
  return NextResponse.json(payload);
}
```

**Three concepts to lock in:**

1. **`CRON_SECRET` is how Vercel secures scheduled routes.** Set it in your Vercel environment variables, and Vercel's cron scheduler automatically sends `Authorization: Bearer <your-secret>` on each invocation. Your route rejects all other callers with a 401. This is the canonical pattern — don't roll your own auth here.

2. **`Date.now()` before and after the `fetch` = wall-clock latency.** `durationMs` tells you not just whether the webhook is alive, but whether it's slow. A 2000ms probe against something that should answer in 50ms is a signal worth alerting on.

3. **Wrap the timer in `try/catch`, not just the status check.** If the fetch throws (network error, timeout), you still want to record how long it waited before failing — `durationMs = Date.now() - start` belongs in both branches.

**Set the secret locally:**

```bash
# .env.local
CRON_SECRET=your-local-secret-here
```

**Test the auth:**
