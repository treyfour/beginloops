**Add HMAC-SHA256 signature verification to `app/api/webhooks/route.ts` so your handler rejects requests that didn't come from GitHub.**

Today's focus: **Webhooks — securing the endpoint with GitHub's signature protocol**

Your webhook handler currently accepts *any* POST request. That means anyone who discovers the URL can send fake events. GitHub prevents this by signing every request with a secret you share with them — your server re-computes the signature and rejects the request if it doesn't match. Here's how to add it:

```ts
// app/api/webhooks/route.ts — add at the top and call before processing

import crypto from "node:crypto";

async function verifyGitHubSignature(req: NextRequest): Promise<boolean> {
  const secret = process.env.GITHUB_WEBHOOK_SECRET;
  if (!secret) return false; // fail closed: no secret = reject everything

  const signature = req.headers.get("x-hub-signature-256");
  if (!signature) return false;

  const body = await req.text(); // must read as text to hash the raw bytes
  const expected =
    "sha256=" +
    crypto.createHmac("sha256", secret).update(body).digest("hex");

  // timingSafeEqual prevents timing attacks
  return crypto.timingSafeEqual(
    Buffer.from(signature),
    Buffer.from(expected)
  );
}

// Then at the top of POST():
export async function POST(req: NextRequest) {
  const verified = await verifyGitHubSignature(req);
  if (!verified) {
    return NextResponse.json({ error: "Forbidden" }, { status: 403 });
  }

  // ⚠️  req.body is now consumed — you already called req.text() above.
  // Replace `await req.json()` with: const body = JSON.parse(await req.text())
  // or clone the request before passing it to the verify function.
  ...
}
```

**Set the secret in two places:**
1. Vercel dashboard → Environment Variables → `GITHUB_WEBHOOK_SECRET=<random string>`
2. GitHub → your repo → Settings → Webhooks → your webhook → Secret field (same value)

**Why this matters:** This is the standard security layer for *all* webhook integrations — Stripe, Twilio, Shopify all use the same HMAC pattern. You also encounter `timingSafeEqual` here for the first time: a regular `===` comparison leaks timing information that an attacker can exploit. Understanding this now means you'll recognize and write it correctly for every webhook you ever build.
