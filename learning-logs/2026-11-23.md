Today's focus: **Heartbeats — persisting and exposing heartbeat state**

Right now, the heartbeat cron fires, checks the webhook endpoint, and logs a JSON payload to the console. That log disappears once the serverless function exits. The classic next step in uptime monitoring is to give that signal a place to land — a "last seen alive" record you can query.

Create `app/api/status/route.ts`:

```ts
import { NextRequest, NextResponse } from "next/server";

// Module-level in-memory store — resets on cold start, good enough to learn the pattern
let lastHeartbeat: {
  status: "ok" | "degraded";
  timestamp: string;
  checks: Record<string, string>;
} | null = null;

export async function GET() {
  if (!lastHeartbeat) {
    return NextResponse.json({ status: "unknown", message: "No heartbeat received yet" }, { status: 503 });
  }
  return NextResponse.json(lastHeartbeat);
}

export async function POST(req: NextRequest) {
  const secret = req.headers.get("x-internal-secret");
  if (secret !== process.env.INTERNAL_SECRET) {
    return NextResponse.json({ error: "Unauthorized" }, { status: 401 });
  }
  lastHeartbeat = await req.json();
  return NextResponse.json({ saved: true });
}
```

Then update `app/api/cron/heartbeat/route.ts` to POST the payload to `/api/status` after computing it:

```ts
await fetch(`${base}/api/status`, {
  method: "POST",
  headers: {

    "x-internal-secret": process.env.INTERNAL_SECRET ?? "",
  },
  body: JSON.stringify(payload),

```

Add `INTERNAL_SECRET=<a-random-string>` to `.env.local`. Now `GET /api/status` returns the last heartbeat result — your UI's `useHeartbeat` hook can poll this endpoint instead of calling the cron directly.

**Why this matters:** Heartbeats are only useful if something can read them. The pattern here — a writer (cron) and a reader (status endpoint) separated by a simple shared record — is the foundation of every uptime dashboard, dead man's switch, and health-check page you will ever build. The in-memory store is intentionally simple: once you understand the shape of the data, swapping it for a database row or a KV entry like Vercel KV is a one-line change.
