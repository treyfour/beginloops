Today's focus: **Hooks — `useEffect` for live polling**

Your heartbeat endpoint already returns a real `ok` / `degraded` JSON payload. The missing piece is a UI that reads it. `useEffect` is the right tool: it runs *after* render, and its cleanup function lets you stop the interval when the component unmounts — no memory leaks.

**Replace `app/page.tsx` with:**

```tsx
"use client";
import { useEffect, useState } from "react";

interface HeartbeatPayload {
  status: "ok" | "degraded";
  timestamp: string;
  checks: { webhookEndpoint: "ok" | "unreachable" };
}

export default function StatusPage() {
  const [data, setData] = useState<HeartbeatPayload | null>(null);

  useEffect(() => {
    const poll = async () => {
      try {
        const res = await fetch("/api/cron/heartbeat");
        setData(await res.json());
      } catch {
        // network error — leave previous state in place
      }
    };

    poll(); // run immediately on mount
    const id = setInterval(poll, 30_000); // then every 30 s
    return () => clearInterval(id); // cleanup on unmount
  }, []); // [] = run once on mount, not on every render

  const color = data?.status === "ok" ? "green" : "red";

  return (
    <main style={{ fontFamily: "monospace", padding: "2rem" }}>
      <h1>beginloops status</h1>
      {data ? (
        <>
          <p>
            Webhook endpoint:{" "}
            <strong style={{ color }}>{data.checks.webhookEndpoint}</strong>
          </p>
          <p>Last checked: {new Date(data.timestamp).toLocaleString()}</p>
        </>
      ) : (
        <p>Checking…</p>
      )}
    </main>
  );
}
```

**Why this matters:** `useEffect` is how React components talk to the outside world — APIs, timers, browser events. The empty `[]` dependency array means "run once on mount." The returned cleanup function is the key insight: without `clearInterval`, every navigation away from and back to the page stacks another interval. Learning this pattern pays off in every real-world React component you'll ever write.
