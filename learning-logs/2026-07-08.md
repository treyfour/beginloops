Add HMAC signature verification to your webhook handler — this teaches you the security handshake that every real webhook system uses.

```ts
// app/api/webhooks/route.ts — add this helper before your POST handler

async function verifySignature(req: NextRequest, rawBody: string): Promise<boolean> {
  const sig = req.headers.get("x-hub-signature-256");
  if (!sig || !process.env.WEBHOOK_SECRET) return false;

  const encoder = new TextEncoder();
  const key = await crypto.subtle.importKey(
    "raw",
    encoder.encode(process.env.WEBHOOK_SECRET),
    { name: "HMAC", hash: "SHA-256" },
    false,
    ["sign"]
  );
  const mac = await crypto.subtle.sign("HMAC", key, encoder.encode(rawBody));
  const expected =
    "sha256=" +
    Array.from(new Uint8Array(mac))
      .map((b) => b.toString(16).padStart(2, "0"))
      .join("");

  // Constant-time compare to prevent timing attacks
  return sig.length === expected.length && sig === expected;
}

// Then update your POST handler to read raw text first:
export async function POST(req: NextRequest) {
  const rawBody = await req.text();
  const isValid = await verifySignature(req, rawBody);
  if (!isValid) {
    return NextResponse.json({ error: "Invalid signature" }, { status: 401 });
  }
  const body = JSON.parse(rawBody);
  // ... rest of your existing handler
}
```

Add `WEBHOOK_SECRET` to `.env.local` and to your Vercel project's environment variables. Set it to the same secret you configure in your GitHub webhook settings.

**Why this matters:** Without signature verification, anyone who discovers your webhook URL can send fake events — fake pushes, fake payments, fake deploys. HMAC-SHA256 is how GitHub, Stripe, Twilio, and virtually every webhook provider prove a request actually came from them. The constant-time comparison is equally important: naive string comparison leaks timing information an attacker can exploit to forge signatures one byte at a time. Once you understand this pattern, every webhook integration you ever read will look familiar.
