Today's focus: **Hooks — encapsulating async polling logic in a reusable React hook**

You already have the server-side heartbeat route. Now close the loop by consuming it from the UI. A custom hook is the idiomatic React pattern for encapsulating any stateful, side-effect-heavy logic (like polling) that multiple components might need:

```ts
// app/hooks/useHeartbeat.ts

import { useEffect, useRef, useState } from "react";

type HeartbeatStatus = "idle" | "ok" | "degraded" | "error";

export function useHeartbeat(intervalMs = 30_000) {
  const [status, setStatus] = useState<HeartbeatStatus>("idle");
  const [lastChecked, setLastChecked] = useState<Date | null>(null);
  const timerRef = useRef<ReturnType<typeof setInterval> | null>(null);

  async function check() {
    try {
      const res = await fetch("/api/cron/heartbeat");
      const data = await res.json();
      setStatus(data.status === "ok" ? "ok" : "degraded");
    } catch {
      setStatus("error");
    } finally {
      setLastChecked(new Date());
    }
  }

  useEffect(() => {
    check(); // fire immediately on mount
    timerRef.current = setInterval(check, intervalMs);
    return () => {
      if (timerRef.current) clearInterval(timerRef.current); // cleanup on unmount
    };
  }, [intervalMs]);

  return { status, lastChecked };
}
```

Then use it in any component:

```tsx
// anywhere in your app
const { status, lastChecked } = useHeartbeat();
// status: "ok" | "degraded" | "error" | "idle"
```

**Why this matters:** Custom hooks are how you reuse async logic without repeating `useEffect`/`useState` boilerplate. The cleanup return in `useEffect` is critical — without it the interval fires after the component unmounts and you get "can't call setState on an unmounted component" warnings. This pattern (poll → display → cleanup) appears everywhere: stock tickers, presence indicators, CI status badges.
