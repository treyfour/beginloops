Today's focus: **Heartbeats — surfacing health data in the UI**

Your heartbeat endpoint already returns a structured payload. The next step is to make that data visible. Open `app/page.tsx` and add a status badge that polls the endpoint and reflects the current health:

```tsx
"use client";
import { useEffect, useState } from "react";

type HeartbeatPayload = {
  status: "ok" | "degraded";
  timestamp: string;
  checks: { webhookEndpoint: "ok" | "unreachable" };
};

export default function Home() {
  const [health, setHealth] = useState<HeartbeatPayload | null>(null);

  useEffect(() => {
    const poll = async () => {
      try {
        const res = await fetch("/api/cron/heartbeat");
        setHealth(await res.json());
      } catch {
        setHealth(null);
      }
    };
    poll();
    const id = setInterval(poll, 30_000);
    return () => clearInterval(id);
  }, []);

  const color = health?.status === "ok" ? "green" : "red";
  return (
    <main>
      <span style={{ color }}>
        {health ? `● ${health.status} — ${health.timestamp}` : "checking…"}
      </span>
    </main>
  );
}
```

Why this matters: a heartbeat without a viewer is just a log line. Wiring it to a React component teaches `useEffect` cleanup (the `clearInterval` return), client-directive boundaries (`"use client"`), and the pattern every real-time dashboard is built on. Once this works, swap `setInterval` for an SSE stream or a WebSocket for push-based updates instead of pull.
