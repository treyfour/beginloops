**Add a second cron route at `app/api/cron/daily-summary/route.ts` and register it in `vercel.json` — this teaches you how to schedule multiple crons, how Vercel fires them (plain GET requests), and how crons differ from webhooks (time-triggered vs event-triggered).**

**Step 1 — Create `app/api/cron/daily-summary/route.ts`:**

```ts
import { NextResponse } from "next/server";

export async function GET() {
  const base = process.env.VERCEL_URL
    ? `https://${process.env.VERCEL_URL}`
    : "http://localhost:3000";

  // Probe the heartbeat endpoint to get webhook health
  let health: "ok" | "degraded" | "unknown" = "unknown";
  try {
    const res = await fetch(`${base}/api/cron/heartbeat`);
    if (res.ok) {
      const data = await res.json();
      health = data.status ?? "unknown";
    }
  } catch {
    health = "unknown";
  }

  const summary = {
    date: new Date().toISOString().slice(0, 10),
    generatedAt: new Date().toISOString(),
    webhookHealth: health,
    message: `Daily summary for ${new Date().toLocaleDateString("en-US", {
      weekday: "long",
      month: "long",
      day: "numeric",
    })}`,
  };

  console.log("[daily-summary]", JSON.stringify(summary, null, 2));
  return NextResponse.json(summary);
}
```

**Step 2 — Register it in `vercel.json` alongside the heartbeat:**

```json
{
  "crons": [
    {
      "path": "/api/cron/heartbeat",
      "schedule": "0 16 * * *"
    },
    {
      "path": "/api/cron/daily-summary",
      "schedule": "5 16 * * *"
    }
  ]
}
```

The `5 16 * * *` schedule fires 5 minutes after the heartbeat — so by the time daily-summary runs, the heartbeat has already logged its result.

**Step 3 — Test it locally:**

```bash
npm run dev

# In another terminal:
curl http://localhost:3000/api/cron/daily-summary | jq .
```

You should see a JSON response with today's date, generation timestamp, and webhook health status.

**Why this matters:** Vercel crons are just scheduled HTTP GET requests to your own API routes — there's no special runtime, no background process, no worker thread. That simplicity is the lesson: time-triggered routes and event-triggered routes (webhooks) share the same shape, the same handler pattern, the same response format. The only difference is who calls them and when. Once you see that crons, webhooks, and heartbeats are all "HTTP handlers with different callers," the whole category of event-driven systems clicks into place.
