Today's focus: **Crons — locking down your cron endpoint**

Right now `/api/cron/heartbeat` is publicly accessible — anyone can `curl` it and trigger your heartbeat logic. Vercel automatically injects an `Authorization: Bearer <CRON_SECRET>` header on every cron invocation. All you have to do is check for it:

```ts
// app/api/cron/heartbeat/route.ts
import { NextResponse } from "next/server";

export async function GET(request: Request) {
  // Reject anything that isn't Vercel's cron runner
  const authHeader = request.headers.get("authorization");
  if (authHeader !== `Bearer ${process.env.CRON_SECRET}`) {
    return NextResponse.json({ error: "Unauthorized" }, { status: 401 });
  }

  // ... rest of heartbeat logic unchanged
}
```

Then add the secret to your Vercel project:
- Vercel Dashboard → your project → Settings → Environment Variables
- Add `CRON_SECRET` with a long random value (e.g. `openssl rand -hex 32`)
- Vercel injects it automatically on every cron invocation — you don't have to set the header yourself

**Why this matters:** Without this check, anyone who discovers your cron URL can spam it, trigger side effects (external API calls, DB writes, pings to healthchecks.io), or use it to probe your internal network. It's a one-line fix with real security impact.

> **Production tip:** For local development, add `CRON_SECRET=dev-secret` to `.env.local` and call the endpoint with `Authorization: Bearer dev-secret`. This keeps the same code path in all environments without special-casing `localhost`.
