Today's focus: **Crons — multiple schedules and aggregation jobs**

Your `vercel.json` currently schedules one cron. Real apps often need several: a heartbeat every few minutes, a digest every week, a cleanup job every night. Each entry maps a path to a cron expression.

Add to `vercel.json`:

```json
{
  "crons": [
    { "path": "/api/cron/heartbeat",      "schedule": "0 16 * * *"  },
    { "path": "/api/cron/weekly-digest",  "schedule": "0 9 * * 1"   }
  ]
}
```

`0 9 * * 1` = every Monday at 09:00 UTC. Create `app/api/cron/weekly-digest/route.ts`:

```ts
import { NextResponse } from "next/server";
import { readdir, readFile } from "fs/promises";
import path from "path";

export async function GET() {
  const logsDir = path.join(process.cwd(), "learning-logs");
  const files = (await readdir(logsDir))
    .filter((f) => f.endsWith(".md"))
    .sort()
    .slice(-7); // last 7 days

  const entries = await Promise.all(
    files.map(async (f) => {
      const text = await readFile(path.join(logsDir, f), "utf-8");
      const title = text.split("\n")[0].replace(/^# /, "");
      return { date: f.replace(".md", ""), title };
    })
  );

  console.log("[weekly-digest]", JSON.stringify({ week: entries }));
  return NextResponse.json({ entries, count: entries.length });
}
```

> **Note:** `process.cwd()` is the project root on Vercel. `fs/promises` is fine in Route Handlers — they run in Node.js, not in the browser.

**Why this matters:** Cron expressions (`minute hour day-of-month month day-of-week`) are the universal language for scheduled work — the same syntax powers Linux cron, GitHub Actions schedules, and Vercel. Building an aggregation job alongside a heartbeat shows the two most common cron patterns: *liveness checks* (run often, fail fast) and *batch jobs* (run rarely, do meaningful work). Once you have two crons, you understand how to have twenty.
