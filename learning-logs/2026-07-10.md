Add HMAC-SHA256 signature verification to `app/api/webhooks/route.ts` — every production webhook consumer does this to confirm the payload actually came from GitHub and not an arbitrary caller.

```ts
// app/api/webhooks/route.ts  (top of file)
import crypto from "crypto";
import { NextRequest, NextResponse } from "next/server";

function verifySignature(payload: string, sig: string | null): boolean {
  const secret = process.env.GITHUB_WEBHOOK_SECRET;
  if (!secret || !sig) return false;
  const expected = `sha256=${crypto
    .createHmac("sha256", secret)
    .update(payload)
    .digest("hex")}`;
  // timingSafeEqual prevents byte-by-byte timing attacks on the comparison
  return crypto.timingSafeEqual(Buffer.from(sig), Buffer.from(expected));
}

export async function POST(req: NextRequest) {
  const rawBody = await req.text(); // must read as text BEFORE JSON.parse
  const sig = req.headers.get("x-hub-signature-256");

  if (!verifySignature(rawBody, sig)) {
    return NextResponse.json({ error: "Invalid signature" }, { status: 401 });
```

Set `GITHUB_WEBHOOK_SECRET` in your Vercel environment variables to the same secret you enter when configuring the webhook on GitHub (`github.com → repo → Settings → Webhooks`).

**Why this matters:** `crypto.timingSafeEqual` instead of `===` is the key detail — a plain string comparison leaks how many leading bytes matched, letting an attacker brute-force the secret one byte at a time. This HMAC pattern is identical across Stripe, GitHub, Twilio, and every major API, so learning it once here means you know it everywhere.
