## Suggested next step

**Add HMAC-SHA256 signature verification to your webhook handler — without it, anyone can send fake events to your endpoint.**

Today's focus: **Webhooks — verifying the sender is who they say they are**

Add this to `app/api/webhooks/route.ts` before the `POST` handler reads the body:

```ts
import { createHmac, timingSafeEqual } from "crypto";

async function verifyGitHubSignature(req: NextRequest): Promise<boolean> {
  const secret = process.env.GITHUB_WEBHOOK_SECRET;
  if (!secret) return false;                          // reject if secret not set

  const sig = req.headers.get("x-hub-signature-256");
  if (!sig) return false;

  const body = await req.text();                       // read raw bytes, not JSON
  const expected = "sha256=" + createHmac("sha256", secret).update(body).digest("hex");

  // timingSafeEqual prevents timing attacks
  return timingSafeEqual(Buffer.from(sig), Buffer.from(expected));
}

export async function POST(req: NextRequest) {
  if (!(await verifyGitHubSignature(req))) {
    return NextResponse.json({ error: "invalid signature" }, { status: 401 });
  }
  // ... rest of handler
}
```

Set `GITHUB_WEBHOOK_SECRET` in your Vercel environment variables and in GitHub → Settings → Webhooks → Secret to the same random string (use `openssl rand -hex 32` to generate one).

**Why this matters:** GitHub signs every webhook delivery with an HMAC of the payload using your shared secret. Without this check, any attacker who discovers your endpoint URL can forge a push event and trigger your handler. `timingSafeEqual` is essential — a plain string comparison leaks timing information that lets an attacker brute-force the signature one byte at a time. This pattern applies to Stripe, Linear, and virtually every webhook provider.
