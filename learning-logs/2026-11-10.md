Today's focus: **Webhooks — verifying that incoming requests actually came from GitHub**

GitHub signs every webhook delivery with a secret you configure. Here's how to verify it:

```ts
// app/api/webhooks/route.ts
import { NextRequest, NextResponse } from "next/server";
import { createHmac, timingSafeEqual } from "crypto";

function verifyGitHubSignature(payload: string, signature: string | null): boolean {
  if (!signature) return false;
  const secret = process.env.GITHUB_WEBHOOK_SECRET;
  if (!secret) return false;
  const expected = "sha256=" + createHmac("sha256", secret).update(payload).digest("hex");
  return timingSafeEqual(Buffer.from(expected), Buffer.from(signature));
}

export async function POST(req: NextRequest) {
  const rawBody = await req.text();
  const sig = req.headers.get("x-hub-signature-256");

  if (!verifyGitHubSignature(rawBody, sig)) {
    return NextResponse.json({ error: "Invalid signature" }, { status: 401 });
  }

  const payload = JSON.parse(rawBody);
  console.log("[webhook] event:", req.headers.get("x-github-event"), payload);
  return NextResponse.json({ ok: true });
}
```

**Why `timingSafeEqual`?** A regular `===` comparison leaks timing information — an attacker can figure out the correct signature byte-by-byte by measuring how long the comparison takes. `timingSafeEqual` always takes the same amount of time regardless of where the strings differ.

**Setup:** In your GitHub repo → Settings → Webhooks → add a webhook, set the secret to a random string, and add that same value to Vercel as `GITHUB_WEBHOOK_SECRET`. Now only GitHub can trigger your handler.

**Why this matters:** Webhook endpoints are public URLs. Without signature verification, anyone who discovers the URL can send fake events — triggering deployments, sending bogus notifications, or worse. Signature verification is the minimum security baseline for any production webhook.
