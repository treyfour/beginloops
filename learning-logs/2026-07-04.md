## Suggested next step
Add HMAC signature verification to `app/api/webhooks/route.ts` so your endpoint only accepts requests from trusted senders (e.g. GitHub or Stripe).

```ts
// app/api/webhooks/route.ts  — add this helper at the top
import { createHmac, timingSafeEqual } from "crypto";

function verifySignature(body: string, signature: string | null, secret: string): boolean {
  if (!signature) return false;
  const expected = "sha256=" + createHmac("sha256", secret).update(body).digest("hex");
  try {
    return timingSafeEqual(Buffer.from(signature), Buffer.from(expected));
  } catch {
    return false; // buffers different lengths → invalid
  }
}

// Inside your POST handler, before doing anything with the body:
export async function POST(req: Request) {
  const rawBody = await req.text();
  const sig = req.headers.get("x-hub-signature-256"); // GitHub's header name
  const secret = process.env.WEBHOOK_SECRET ?? "";

  if (!verifySignature(rawBody, sig, secret)) {
    return new Response("Unauthorized", { status: 401 });
  }

  const payload = JSON.parse(rawBody);
  // ... rest of your existing handler
}
```

Then add `WEBHOOK_SECRET` to your Vercel environment variables and set it in GitHub (repo → Settings → Webhooks → Secret).

**Why this matters:** Without signature verification, anyone who discovers your `/api/webhooks` URL can POST fake events — fake deploys, fake payment confirmations, fake CI results. HMAC verification cryptographically proves the request came from the sender who holds the shared secret. Note `timingSafeEqual` instead of `===`: a plain string comparison leaks timing information that lets an attacker brute-force the signature byte by byte. This is the one security detail that trips up nearly every webhook implementation — getting it right from the start is the professional habit.
