## Suggested next step
**Secure the cron endpoint — add `CRON_SECRET` verification to `app/api/cron/heartbeat/route.ts` so only Vercel (not the public internet) can trigger it.**

Right now anyone who knows the URL can POST to your heartbeat cron and trigger it on demand. Vercel protects cron routes automatically when you opt in to their secret header — one environment variable and three lines of code.

**1. Add the secret to your Vercel environment variables** (or `.env.local` for local dev):
```
CRON_SECRET=some-long-random-string
```

**2. Update `vercel.json`** so Vercel injects the header on each scheduled invocation:
```json
{
  "crons": [
    {
      "path": "/api/cron/heartbeat",
      "schedule": "* * * * *"
    }
  ]
}
```
Vercel automatically sends `Authorization: Bearer <CRON_SECRET>` when it invokes cron routes — no extra config needed beyond setting the env var.

**3. Add the guard at the top of your cron handler:**
```ts
// app/api/cron/heartbeat/route.ts
import { NextRequest, NextResponse } from "next/server";

export async function GET(req: NextRequest) {
  const auth = req.headers.get("authorization");
  if (auth !== `Bearer ${process.env.CRON_SECRET}`) {
    return NextResponse.json({ error: "Unauthorized" }, { status: 401 });
  }

  // ... rest of your existing heartbeat logic
}
```

**Why this matters:** Without this check, any bot that port-scans `/api/cron/heartbeat` can hammer your endpoint — running up serverless invocation costs, polluting your logs, or causing unintended side effects. The `CRON_SECRET` pattern is Vercel's official recommendation and takes under five minutes to wire up. It also pairs naturally with yesterday's HMAC suggestion: once both endpoints verify their callers, the entire pipeline — GitHub → webhook → cron → heartbeat — is authenticated end-to-end.
