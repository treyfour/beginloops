## Suggested next step
Add a second cron job to `vercel.json` and a new route `app/api/cron/daily-summary/route.ts` that runs at midnight UTC — this teaches you how Vercel schedules multiple independent jobs and what each cron invocation receives.

```json
// vercel.json — add the second entry
{
  "crons": [
    { "path": "/api/cron/heartbeat",     "schedule": "0 16 * * *" },
    { "path": "/api/cron/daily-summary", "schedule": "0 0 * * *"  }
  ]
}
```

```ts
// app/api/cron/daily-summary/route.ts
export const runtime = "edge"; // optional — runs closer to the user

export async function GET(req: Request) {
  // Vercel attaches this header on every cron invocation.
  // Check it so only the scheduler (not random browsers) can trigger the route.
  const isVercelCron = req.headers.get("x-vercel-cron") === "1";
  if (!isVercelCron && process.env.NODE_ENV === "production") {
    return new Response("Forbidden", { status: 403 });
  }

  const summary = {
    date: new Date().toISOString().slice(0, 10), // "YYYY-MM-DD"
    message: "Daily summary cron fired successfully",
    nextSteps: ["fetch heartbeat history", "email report", "post to Slack"],
  };

  console.log("[daily-summary]", JSON.stringify(summary));
  return Response.json(summary);
}
```

**Why this matters:** Real applications almost always need more than one scheduled job — a heartbeat every hour, a report at midnight, a cleanup job on Sundays. Adding a second cron entry is the moment you go from "I have a cron" to "I understand cron scheduling." The `x-vercel-cron` header check is the cron equivalent of HMAC verification: it ensures your route only runs when the scheduler fires it, not when someone discovers the URL. Once this is in place you can fill the body with real work — aggregate heartbeat results, send a Slack message, or write to a database.
