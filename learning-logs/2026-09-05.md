Today's focus: **Custom React hooks — connecting your API routes to the frontend**

You've built two API routes (`/api/webhooks` and `/api/cron/heartbeat`) but the frontend hasn't touched them yet. A custom hook is the idiomatic React way to wrap async, stateful logic — and polling a status endpoint is a perfect first hook to write because it teaches `useState`, `useEffect`, and cleanup in one exercise.

**Create `app/hooks/useHeartbeat.ts`:**

```ts
import { useState, useEffect } from "react";

interface HeartbeatStatus {
  status: "ok" | "degraded" | "loading" | "error";
  timestamp: string | null;
  checks: { webhookEndpoint: "ok" | "unreachable" } | null;
}

export function useHeartbeat(intervalMs = 10_000) {
  const [data, setData] = useState<HeartbeatStatus>({
    status: "loading",
    timestamp: null,
    checks: null,
  });

  useEffect(() => {
    let cancelled = false;

    async function poll() {
      try {
        const res = await fetch("/api/cron/heartbeat");
        if (!res.ok) throw new Error(`HTTP ${res.status}`);
        const json = await res.json();
        if (!cancelled) setData(json);
      } catch {
        if (!cancelled) setData((prev) => ({ ...prev, status: "error" }));
      }
    }

    poll(); // run immediately on mount
    const id = setInterval(poll, intervalMs);

    return () => {
      cancelled = true; // prevent stale setState after unmount
      clearInterval(id);
    };
  }, [intervalMs]);

  return data;
}
```

**Then use it in `app/page.tsx`:**

```tsx
import { useHeartbeat } from "./hooks/useHeartbeat";

export default function Home() {
  const { status, timestamp, checks } = useHeartbeat(10_000);
  const color = status === "ok" ? "green" : status === "loading" ? "gray" : "red";

  return (
    <main>
      <h1>beginloops</h1>
      <p style={{ color }}>
        API status: <strong>{status}</strong>
      </p>
      {timestamp && <p>Last checked: {new Date(timestamp).toLocaleTimeString()}</p>}
      {checks && <p>Webhook endpoint: {checks.webhookEndpoint}</p>}
    </main>
  );
}
```

**Three concepts to lock in:**

1. **`useEffect` cleanup** — the function returned from `useEffect` runs when the component unmounts (or before the effect re-runs). Always clear your interval there, and use a `cancelled` flag to prevent calling `setState` on an unmounted component — a very common source of React warnings.

2. **Polling vs. webhooks** — polling is the client *asking* the server "anything new?" on a timer; webhooks are the server *telling* the client something happened. Your heartbeat hook polls. Your `/api/webhooks` route receives webhooks. Both patterns are useful; now you have one of each.

3. **Custom hooks are just functions** — a hook is a regular JS function that starts with `use` and can call other hooks. Extracting `useHeartbeat` from `page.tsx` means any page or component can import it with one line, and the polling logic lives in exactly one place.
