Today's focus: **Heartbeats (Cron Security)**

Vercel's cron runner automatically injects an `Authorization: Bearer <CRON_SECRET>` header on every scheduled request. If you validate that header in your handler, you can reject anything that didn't originate from Vercel's scheduler. Without this check, anyone who discovers your `/api/cron/heartbeat` URL can trigger your cron logic manually — a minor nuisance today (it just logs a status), but a real problem once crons do anything expensive like sending emails or making paid API calls.

**Step 1 — Generate and store the secret:**
```bash
# Generate a random secret
openssl rand -base64 32
```

Add it to `.env.local`:
```
CRON_SECRET=your-generated-secret-here
```

Then set the same value in the Vercel dashboard under **Settings → Environment Variables**, marking it as available to Production (and Preview if you want).

**Step 2 — Update `app/api/cron/heartbeat/route.ts`:**
```ts
import { NextRequest, NextResponse } from "next/server";

export async function GET(req: NextRequest) {
  // Reject requests that don't carry the correct cron secret
  const authHeader = req.headers.get("authorization");
  if (authHeader !== `Bearer ${process.env.CRON_SECRET}`) {
    return NextResponse.json({ error: "Unauthorized" }, { status: 401 });
  }

  const base = process.env.VERCEL_URL
    ? `https://${process.env.VERCEL_URL}`
    : "http://localhost:3000";

  let webhookStatus: "ok" | "unreachable" = "unreachable";
  try {
    const res = await fetch(`${base}/api/webhooks`, {
      method: "POST",
      headers: { "Content-Type": "application/json", "x-github-event": "ping" },
      body: JSON.stringify({ zen: "heartbeat probe" }),
    });
    webhookStatus = res.ok ? "ok" : "unreachable";
  } catch {
    webhookStatus = "unreachable";
  }

  const payload = {
    status: webhookStatus === "ok" ? "ok" : "degraded",
    timestamp: new Date().toISOString(),
    checks: { webhookEndpoint: webhookStatus },
  };

  console.log("[heartbeat]", JSON.stringify(payload));
  return NextResponse.json(payload);
}
```

**Step 3 — Test it locally:**
```bash
# Should return 401
curl http://localhost:3000/api/cron/heartbeat

# Should return the status payload
curl -H "Authorization: Bearer your-generated-secret-here" \
  http://localhost:3000/api/cron/heartbeat
```

**Why the env-var check alone is enough:** You don't need IP allowlisting or anything more complex. The secret is a shared secret between Vercel's scheduler and your handler — anyone without it gets a 401. Vercel's docs for this pattern are at [vercel.com/docs/cron-jobs/manage-cron-jobs#securing-cron-jobs](https://vercel.com/docs/cron-jobs/manage-cron-jobs#securing-cron-jobs).

**Dev tip:** On `localhost`, `CRON_SECRET` is `undefined` unless you've added it to `.env.local`. The check above blocks all unauthenticated local requests, which is the safe default — just remember to pass the header in your local `curl` commands or API client when testing.
