**Add HMAC-SHA256 signature verification to `app/api/webhooks/route.ts` — reject any request that GitHub didn't actually sign.**

Right now the endpoint accepts any POST from anyone. GitHub signs every webhook delivery with a `X-Hub-Signature-256` header using a shared secret you configure. Verifying that signature is the first thing real webhook handlers do.

**1. Set a secret in your Vercel environment variables** (or `.env.local` for local dev):
```
GITHUB_WEBHOOK_SECRET=some-long-random-string
```

**2. Replace the POST handler in `app/api/webhooks/route.ts`:**
```ts
import { NextRequest, NextResponse } from "next/server";

async function verifySignature(req: NextRequest, rawBody: string): Promise<boolean> {
  const secret = process.env.GITHUB_WEBHOOK_SECRET;
  if (!secret) return false;

  const sig = req.headers.get("x-hub-signature-256") ?? "";
  const encoder = new TextEncoder();
  const key = await crypto.subtle.importKey(
    "raw",
    encoder.encode(secret),
    { name: "HMAC", hash: "SHA-256" },
    false,
    ["sign"]
  );
  const mac = await crypto.subtle.sign("HMAC", key, encoder.encode(rawBody));
  const expected = "sha256=" + Array.from(new Uint8Array(mac))
    .map((b) => b.toString(16).padStart(2, "0"))
    .join("");

  // Constant-time comparison prevents timing attacks
  return sig.length === expected.length && sig === expected;
}

export async function POST(req: NextRequest) {
  const rawBody = await req.text();

  if (!(await verifySignature(req, rawBody))) {
    return NextResponse.json({ error: "Unauthorized" }, { status: 401 });
```

**Why this matters:** Without signature verification, anyone who discovers your webhook URL can POST arbitrary payloads — triggering CI, spoofing commits, or causing unintended side effects. HMAC-SHA256 with a shared secret ensures only GitHub (who knows the secret) can send valid events. This is the industry-standard pattern used by GitHub, Stripe, Twilio, and every other major webhook provider. The `crypto.subtle` API used here is the Web Crypto standard available in the Next.js Edge and Node runtimes — no dependencies required.
