Today's focus: **Heartbeats (as an observability instrument, not just a liveness check)**

Your heartbeat already tells you *whether* the webhook endpoint is reachable. Latency tells you *how quickly* — and slow latency often signals a problem before a full outage hits. Here is the change:

```ts
import { NextResponse } from "next/server";

export async function GET() {
  const base = process.env.VERCEL_URL
    ? `https://${process.env.VERCEL_URL}`
    : "http://localhost:3000";

  let webhookStatus: "ok" | "unreachable" = "unreachable";
  let durationMs: number | null = null;

  try {
    const start = Date.now();                         // ← start the clock
    const res = await fetch(`${base}/api/webhooks`, {
      method: "POST",
      headers: { "Content-Type": "application/json", "x-github-event": "ping" },
      body: JSON.stringify({ zen: "heartbeat probe" }),
    });
    durationMs = Date.now() - start;                  // ← stop the clock
    webhookStatus = res.ok ? "ok" : "unreachable";
  } catch {
    webhookStatus = "unreachable";
  }

  const payload = {
    status: webhookStatus === "ok" ? "ok" : "degraded",
    timestamp: new Date().toISOString(),
    durationMs,                                       // ← new field
    checks: { webhookEndpoint: webhookStatus },
  };

  console.log("[heartbeat]", JSON.stringify(payload)); // structured JSON log
  return NextResponse.json(payload);
}
```

**Three concepts to lock in:**

1. **`Date.now()` returns milliseconds since the Unix epoch** — subtracting two calls gives you elapsed wall-clock time in ms. This is the simplest latency measurement and perfectly adequate for a heartbeat. For more precision use `performance.now()`, but `Date.now()` is readable and portable.

2. **Structured JSON logs beat string concatenation.** `console.log("[heartbeat]", JSON.stringify(payload))` emits a machine-readable line that Vercel's log viewer (and tools like Datadog or Logtail) can index and alert on. A plain string like `"heartbeat ok 45ms"` looks fine in a terminal but cannot be queried programmatically.

3. **The heartbeat response shape is your API contract.** Once you add `durationMs` to the JSON, the `useCronStatus` hook from yesterday's suggestion can expose it too — add it to the `HeartbeatResult` interface and show it in the UI: "Last checked: 2:14 PM · 43ms". That one-line UI addition makes the health panel genuinely useful instead of decorative.
