Today's focus: **Webhooks — verifying the signature so only trusted senders can trigger your handler**

Right now anyone can POST to `/api/webhooks` and your handler will process it as though GitHub sent it. GitHub signs every delivery with a secret you set in the webhook settings — verifying that signature is the single most important security step for a webhook receiver.

**Step 1 — Store the secret as an environment variable.** Add `WEBHOOK_SECRET=<your-secret>` to `.env.local` (and to your Vercel project's environment variables).

**Step 2 — Add a `verifySignature` helper inside `app/api/webhooks/route.ts`:**

```ts
import { createHmac, timingSafeEqual } from "crypto";

async function verifySignature(req: NextRequest, body: string): Promise<boolean> {
  const secret = process.env.WEBHOOK_SECRET;
  if (!secret) return false;

  const sig = req.headers.get("x-hub-signature-256") ?? "";
  const expected = "sha256=" + createHmac("sha256", secret).update(body).digest("hex");

  // timingSafeEqual prevents timing attacks
  return sig.length === expected.length &&
    timingSafeEqual(Buffer.from(sig), Buffer.from(expected));
}
```

**Step 3 — Read the raw body once and verify before parsing:**

export async function POST(req: NextRequest) {

**Why this matters:** Without signature verification, your webhook endpoint is an open door — any script can send fake push events and trigger your handler logic. `timingSafeEqual` is the detail that makes the check robust: a plain string comparison leaks the signature length through timing; constant-time comparison does not. This same pattern applies to Stripe, Vercel, and every other service that signs its webhook payloads.
