Today's focus: **Crons — locking down who can invoke your cron endpoint**

Right now, anyone who discovers `/api/cron/heartbeat` can hit it with a plain GET request and trigger the probe — or spam it at will. Vercel solves this by automatically injecting a `CRON_SECRET` environment variable into your project and sending it as `Authorization: Bearer <CRON_SECRET>` on every scheduled cron invocation. Checking that header is a one-liner guard that makes the endpoint cron-only.

Add this check at the top of your handler:

```ts
import { NextRequest, NextResponse } from "next/server";

export async function GET(req: NextRequest) {
  // Vercel sets CRON_SECRET automatically; skip the check in local dev when it isn't set
  const cronSecret = process.env.CRON_SECRET;
  if (cronSecret) {
    const auth = req.headers.get("authorization");
    if (auth !== `Bearer ${cronSecret}`) {
      return NextResponse.json({ error: "Unauthorized" }, { status: 401 });
    }
  }

  // ... rest of your handler unchanged
  const base = process.env.VERCEL_URL
    ? `https://${process.env.VERCEL_URL}`
    : "http://localhost:3000";
  // ...
}
```

You don't need to set `CRON_SECRET` yourself — Vercel generates and injects it automatically when your project is deployed. Just read it from `process.env`.

**Why this matters:**
- This is the exact same idea as yesterday's webhook HMAC check: prove the caller is who they claim to be before doing any work.
- The mechanism is different though — a shared Bearer token instead of an HMAC signature — which is a useful contrast: Bearer tokens are simpler but require a secure channel (HTTPS, which Vercel enforces), while HMAC lets you verify the payload wasn't tampered with even if someone intercepts it.
- Together, these two guards cover both external entry points in this app: the webhook endpoint proves the payload came from GitHub, and the cron endpoint proves the trigger came from Vercel.
- Once you add this, your app follows the same pattern most production Next.js apps use — and the pattern generalises to any route you want to restrict to a known internal caller.
