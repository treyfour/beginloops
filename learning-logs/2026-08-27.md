Today's focus: **Webhooks (signature verification)**

Every time GitHub sends an event, it includes an `X-Hub-Signature-256` header containing an HMAC-SHA256 digest of the raw request body, keyed with your webhook secret. Your route currently ignores it — which means anyone who knows your URL can send fake "push" events and your handler will log them as real.

**Step 1 — add a verification helper:**

```ts
import { createHmac, timingSafeEqual } from "crypto";

/**
 * Returns true if the request body matches the X-Hub-Signature-256 header.
 * Uses timingSafeEqual to prevent timing attacks.
 */
function verifyGitHubSignature(
  rawBody: string,
  signature: string | null,
  secret: string
): boolean {
  if (!signature?.startsWith("sha256=")) return false;
  const expected = "sha256=" + createHmac("sha256", secret).update(rawBody).digest("hex");
  const a = Buffer.from(signature);
  const b = Buffer.from(expected);
  // Buffers must be the same length for timingSafeEqual
  return a.length === b.length && timingSafeEqual(a, b);
}
```

**Step 2 — read the raw body and verify before parsing:**

**Three concepts to lock in:**

1. **Why `req.text()` instead of `req.json()`?** HMAC is computed over the *exact bytes* GitHub sent. If you call `req.json()` first, the body is parsed and would need to be re-serialised — whitespace, key order, and unicode escaping may differ. Reading raw text guarantees byte-for-byte fidelity.

2. **Why `timingSafeEqual`?** A naive `===` comparison short-circuits as soon as it finds a mismatch. An attacker can measure those microsecond differences across thousands of requests to reconstruct the expected signature one character at a time (a timing attack). `timingSafeEqual` always runs in constant time regardless of where strings diverge.

3. **Skip verification in local dev.** The `if (secret)` guard means the route still accepts a plain `curl` when `GITHUB_WEBHOOK_SECRET` isn't set locally — so you can keep testing without faking the header during development. In production, Vercel will always have the secret set.

**Test it end-to-end:**

```bash
# Set a local secret just for testing
export GITHUB_WEBHOOK_SECRET=testsecret

# Generate the correct signature (mimics what GitHub sends)
PAYLOAD='{"ref":"refs/heads/main","pusher":{"name":"test","email":"test@test.com"},"before":"abc1234","after":"def5678","commits":[],"repository":{"full_name":"you/repo","html_url":""}}'
SIG="sha256=$(printf '%s' "$PAYLOAD" | openssl dgst -sha256 -hmac testsecret | awk '{print $2}')"

# Send it with the correct signature → 200
curl -X POST http://localhost:3000/api/webhooks \
  -H "Content-Type: application/json" \
  -H "x-github-event: push" \
  -H "x-hub-signature-256: $SIG" \
  -d "$PAYLOAD"

# Send without the header → 401
curl -X POST http://localhost:3000/api/webhooks \
  -H "Content-Type: application/json" \
  -H "x-github-event: push" \
  -d "$PAYLOAD"
```
