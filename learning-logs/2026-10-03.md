Today's focus: **Hooks — connecting your backend cron/heartbeat to a live React UI**

You have a heartbeat endpoint that knows the health of your app — but nothing reads it. The next learning step is building a custom React hook that polls that endpoint and surfaces the result on screen.

Add this to `app/page.tsx`:

```tsx
"use client";

import { useState, useEffect } from "react";

interface HeartbeatStatus {
  status: "ok" | "degraded";
  timestamp: string;
  checks: { webhookEndpoint: "ok" | "unreachable" };
}

function useHeartbeat(intervalMs = 30_000) {
  const [data, setData] = useState<HeartbeatStatus | null>(null);
  const [error, setError] = useState<string | null>(null);

  useEffect(() => {
    async function poll() {
      try {
        const res = await fetch("/api/cron/heartbeat");
        if (!res.ok) throw new Error(`HTTP ${res.status}`);
        setData(await res.json());
        setError(null);
      } catch (e) {
        setError(e instanceof Error ? e.message : "unknown error");
      }
    }

    poll(); // run immediately on mount
    const id = setInterval(poll, intervalMs);
    return () => clearInterval(id); // cleanup on unmount
  }, [intervalMs]);

  return { data, error };
}

export default function Home() {
  const { data, error } = useHeartbeat();

  return (
    <main style={{ padding: "2rem", fontFamily: "monospace" }}>
      <h1>beginloops</h1>
      <h2>Heartbeat</h2>
      {error && <p style={{ color: "red" }}>Error: {error}</p>}
      {data ? (
        <pre>{JSON.stringify(data, null, 2)}</pre>
      ) : (
        <p>Polling…</p>
      )}
    </main>
  );
}
```

**Why this matters:**
- `useEffect` + `setInterval` + `clearInterval` on return is the canonical pattern for any polling loop in React — understanding the cleanup function is critical for avoiding memory leaks.
- A custom hook (`useHeartbeat`) separates data-fetching logic from rendering, which is the same pattern behind `useSWR`, `react-query`, and every production data hook you'll encounter.
- Polling a cron-health endpoint from the frontend is exactly how dashboards and status pages work — you're learning the full loop: cron runs on a schedule → endpoint reports health → UI reflects live state.

Once this renders, you'll see the same `status`/`checks` JSON your heartbeat cron produces, updating live every 30 seconds. That's the cron → server → client data flow made visible.
