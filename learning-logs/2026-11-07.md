Today's focus: **Heartbeats — securing a cron endpoint so only Vercel can invoke it**

Vercel automatically sends an `Authorization: Bearer <CRON_SECRET>` header when it invokes your cron. Add this check at the top of your `GET` handler:

```ts
// app/api/cron/heartbeat/route.ts
import { NextRequest, NextResponse } from "next/server";

export async function GET(req: NextRequest) {
  const secret = process.env.CRON_SECRET;
  if (secret) {
    const auth = req.headers.get("authorization");
    if (auth !== `Bearer ${secret}`) {
      return NextResponse.json({ error: "Unauthorized" }, { status: 401 });
    }
  }

  // ... rest of your existing handler
}
```

Then set `CRON_SECRET` in your Vercel environment variables dashboard. Vercel injects it automatically on cron calls; your local dev skips the check when the env var is absent.

**Why this matters:** An unprotected cron endpoint leaks capacity — anyone can POST to it, run up your function invocations, or probe your internal health checks. The `CRON_SECRET` pattern is Vercel's official recommendation and mirrors how you'd protect any server-to-server callback (webhooks use `x-hub-signature`, crons use bearer tokens — same concept, different transport). Once protected, you can safely expose richer diagnostic data in the response without worrying about information leakage.
