## Suggested next step

**Add HMAC-SHA256 signature verification to `app/api/webhooks/route.ts` so it only accepts requests that prove they came from a trusted sender (like GitHub or Stripe).**

Today's focus: **Webhooks — making your endpoint secure, not just open**

Here is the full implementation:

```ts
// app/api/webhooks/route.ts
import { NextRequest, NextResponse } from "next/server";
import { createHmac, timingSafeEqual } from "crypto";

const SECRET = process.env.WEBHOOK_SECRET ?? "";

function verifySignature(body: string, sigHeader: string | null): boolean {
  if (!sigHeader) return false;
  // GitHub format: "sha256=<hex>"; Stripe format: "t=...,v1=<hex>"
  const expected = createHmac("sha256", SECRET).update(body).digest("hex");
  const received = sigHeader.replace(/^sha256=/, "");
  try {
    return timingSafeEqual(Buffer.from(expected), Buffer.from(received));
  } catch {
    return false;
  }
}

export async function POST(req: NextRequest) {
  const body = await req.text(); // read raw — JSON.parse comes AFTER verification
  const sig = req.headers.get("x-hub-signature-256") ?? req.headers.get("stripe-signature");

  if (!verifySignature(body, sig)) {
    return NextResponse.json({ error: "invalid signature" }, { status: 401 });
  }

  const payload = JSON.parse(body);
  console.log("verified webhook payload:", payload);
  return NextResponse.json({ received: true });
}
```

Add `WEBHOOK_SECRET` to your `.env.local` (and to Vercel's environment variables):

```
WEBHOOK_SECRET=your-secret-here
```

**Why this matters:** Any endpoint on the internet can receive POST requests — without signature verification, anyone can send fake events to your webhook. HMAC verification proves the sender knows your shared secret without transmitting it. `timingSafeEqual` is essential here: a naive `===` comparison leaks timing information that attackers can use to guess the secret one byte at a time. This pattern is used verbatim by GitHub, Stripe, Shopify, and nearly every webhook provider.
