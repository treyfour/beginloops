Today's focus: **Heartbeats (latency tracking — measuring what you monitor)**

A heartbeat that only checks "up or down" is a smoke detector. One that also records *how long the endpoint took to respond* is a smoke detector with a thermometer — you'll know a fire is coming before the alarm sounds. Latency spikes are typically the first sign of a struggling service.

**The full updated route:**

```ts
import { NextResponse } from "next/server";

const LATENCY_WARN_MS = 500;

export async function GET() {
  const base = process.env.VERCEL_URL
    ? `https://${process.env.VERCEL_URL}`
    : "http://localhost:3000";

  let webhookStatus: "ok" | "unreachable" = "unreachable";
  let webhookLatencyMs: number | null = null;

  try {
    const t0 = performance.now();
    const res = await fetch(`${base}/api/webhooks`, {
      method: "POST",
      headers: { "Content-Type": "application/json", "x-github-event": "ping" },
      body: JSON.stringify({ zen: "heartbeat probe" }),
    });
    webhookLatencyMs = Math.round(performance.now() - t0);
    webhookStatus = res.ok ? "ok" : "unreachable";
  } catch {
    webhookStatus = "unreachable";
  }

  if (webhookLatencyMs !== null && webhookLatencyMs > LATENCY_WARN_MS) {
    console.warn(
      `[heartbeat] ⚠️  webhook latency ${webhookLatencyMs}ms exceeds ${LATENCY_WARN_MS}ms threshold`
    );
  }

  const payload = {
    status: webhookStatus === "ok" ? "ok" : "degraded",
    timestamp: new Date().toISOString(),
    checks: {
      webhookEndpoint: webhookStatus,
      webhookLatencyMs,
    },
  };

  console.log("[heartbeat]", JSON.stringify(payload));
  return NextResponse.json(payload);
}
```

**Three concepts to internalize:**

1. **`performance.now()` vs `Date.now()`:** `performance.now()` gives sub-millisecond precision and is monotonic — it never goes backward across clock adjustments. `Date.now()` can jump if the system clock is corrected mid-request. For latency measurement, always use `performance.now()`. It's available in Node.js (18+), Vercel Edge, and the browser.

2. **Why `Math.round()`?** `performance.now()` returns a float like `142.37681`. Rounding to the nearest ms makes logs scannable at a glance and keeps JSON payloads tidy. You lose sub-millisecond detail, but for a heartbeat that detail doesn't matter.

3. **What latency threshold is right?** A rule of thumb for server-to-server calls in the same region: ≤ 50 ms is excellent, 50–200 ms is normal, 200–500 ms is sluggish, > 500 ms is alarming. Since your heartbeat calls your own webhook route, anything consistently above 200 ms suggests a cold-start problem or resource pressure — worth investigating before it becomes an outage.
