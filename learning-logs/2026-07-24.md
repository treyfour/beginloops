## Suggested next step
**Add a second cron endpoint `app/api/cron/daily-summary/route.ts` that fetches recent commits from the GitHub API and logs a digest — this is how real-world crons pull external data on a schedule, not just ping your own server.**

**Step 1 — Create the route:**

```ts
// app/api/cron/daily-summary/route.ts
import { NextResponse } from "next/server";

export async function GET() {
  const repo = "treyfour/beginloops";
  const since = new Date(Date.now() - 24 * 60 * 60 * 1000).toISOString();

  const res = await fetch(
    `https://api.github.com/repos/${repo}/commits?since=${since}&per_page=10`,
    {
      headers: {
        Authorization: `Bearer ${process.env.GITHUB_TOKEN}`,
        Accept: "application/vnd.github+json",
      },
    }
  );

  const commits = res.ok ? await res.json() : [];
  const summary = {
    date: new Date().toISOString().slice(0, 10),
    commitCount: commits.length,
    authors: [...new Set(commits.map((c: { commit: { author: { name: string } } }) => c.commit.author.name))],
    messages: commits.map((c: { commit: { message: string } }) => c.commit.message.split("\n")[0]),
  };

  console.log("[daily-summary]", JSON.stringify(summary));
  return NextResponse.json(summary);
}
```

**Step 2 — Register it in `vercel.json`** so it fires at a different time from the heartbeat:

```json
{
  "crons": [
    { "path": "/api/cron/heartbeat",      "schedule": "0 16 * * *" },
    { "path": "/api/cron/daily-summary",  "schedule": "0 9  * * *" }
  ]
}
```

**Step 3 — Add `GITHUB_TOKEN` to your Vercel project environment variables** (Settings → Environment Variables). Use a fine-grained personal access token with read access to repository contents.

**Step 4 — Test it locally:**

```bash
GITHUB_TOKEN=your_token_here npm run dev
curl http://localhost:3000/api/cron/daily-summary
```

**Why this matters:** Your existing heartbeat cron only talks to itself — it tells you "am I alive?" The next level is a cron that reaches out to an external system and pulls data on a schedule. That's the pattern behind digest emails, nightly reports, and automated monitoring dashboards. Once this works you'll understand the full shape: trigger → fetch → log → (eventually) store or notify.
