## Suggested next step

**Protect your existing cron endpoint from unauthorized calls by reading the `CRON_SECRET` environment variable and rejecting requests that don't carry the right `Authorization` header — this is the missing security layer every cron route needs.**

Today's focus: **Crons — locking down your cron endpoints**

Right now anyone who knows your cron URL can call it, bypassing Vercel's scheduler entirely. Vercel automatically sends `Authorization: Bearer <CRON_SECRET>` on every scheduled invocation — you just need to check it. Adding this check teaches you the full lifecycle of a production cron: schedule → Vercel fires the request → your route validates the caller → it runs.

Update `app/api/cron/heartbeat/route.ts` to add the guard at the top of the `GET` handler:

```ts
import { NextRequest, NextResponse } from "next/server";

function isAuthorized(req: NextRequest): boolean {
  const authHeader = req.headers.get("authorization");
  const secret = process.env.CRON_SECRET;
  if (!secret) return false; // misconfigured — reject
  return authHeader === `Bearer ${secret}`;
}

export async function GET(req: NextRequest) {
  if (!isAuthorized(req)) {
    return NextResponse.json({ error: "Unauthorized" }, { status: 401 });
  }

  // ... rest of your existing heartbeat logic
}
```

Then add `CRON_SECRET` to your `.env.local` for local testing:

```
CRON_SECRET=some-long-random-string
```

And test both sides from the terminal:

```bash
# Should get 401 — no secret
curl http://localhost:3000/api/cron/heartbeat

# Should get 200 — correct secret
curl -H "Authorization: Bearer some-long-random-string" \
     http://localhost:3000/api/cron/heartbeat
```

Finally, add `CRON_SECRET` to your Vercel project's environment variables (Settings → Environment Variables). Vercel will automatically send it on each scheduled invocation.

**Why this matters:** Without this guard, your cron endpoint is a public route — anyone can spam it or trigger side effects (writes, emails, charges) on demand. The `Authorization: Bearer` pattern is the standard Vercel recommends, and understanding it means you can apply the same check to any scheduled route you add in the future. Environment variable injection is also the skill that crosses all four topics: webhooks use `WEBHOOK_SECRET`, crons use `CRON_SECRET`, heartbeat monitors often carry API keys — same pattern every time.
