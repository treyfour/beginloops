## Suggested next step
Add **HMAC-SHA256 signature verification** to the webhook handler — this is the security gate that proves a request genuinely came from GitHub (or Stripe, or any other sender).

In `app/api/webhooks/route.ts`, add this before parsing the body:

```ts
import { createHmac, timingSafeEqual } from "crypto";

function verifySignature(payload: string, signature: string | null, secret: string): boolean {
  if (!signature?.startsWith("sha256=")) return false;
  const expected = "sha256=" + createHmac("sha256", secret).update(payload).digest("hex");
  // timingSafeEqual prevents timing attacks that could leak the secret
  try {
    return timingSafeEqual(Buffer.from(signature), Buffer.from(expected));
  } catch {
    return false; // length mismatch also means invalid
  }
}
```

Then in `POST`, read the raw body as text first (before `req.json()`):

```ts
export async function POST(req: NextRequest) {
  const rawBody = await req.text();
  const sig = req.headers.get("x-hub-signature-256");
  const secret = process.env.GITHUB_WEBHOOK_SECRET ?? "";

  if (!verifySignature(rawBody, sig, secret)) {
    return NextResponse.json({ error: "invalid signature" }, { status: 401 });
  }

  // … rest of handler unchanged
}
```

Add `GITHUB_WEBHOOK_SECRET` to your `.env.local` and match it in GitHub → Settings → Webhooks → Secret.

**Why this matters:** Without signature verification, anyone who knows your deployment URL can forge webhook payloads — triggering deploys, polluting logs, or exploiting downstream logic. `timingSafeEqual` is the subtlety most tutorials skip: a naive `===` comparison leaks timing information that an attacker can use to brute-force the secret one byte at a time. This single function is the same pattern used in GitHub Actions, Stripe, Twilio, and nearly every major webhook provider.
