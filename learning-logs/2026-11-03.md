Today's focus: **Crons — locking down your cron route so it only runs when Vercel fires it**

Your heartbeat endpoint is currently a plain `GET` that anyone can hit. Vercel's Cron service sends an `Authorization: Bearer <CRON_SECRET>` header on every scheduled call. Your route should reject anything that doesn't carry the right token. Here's the pattern:

```ts
// app/api/cron/heartbeat/route.ts — add at the top of your GET handler

export async function GET(req: NextRequest) {
  const cronSecret = process.env.CRON_SECRET;
  const authHeader = req.headers.get("authorization");

  if (!cronSecret || authHeader !== `Bearer ${cronSecret}`) {
    return NextResponse.json({ error: "Unauthorized" }, { status: 401 });
  }

  // ... rest of your existing handler
}
```

Then set the secret in your Vercel project environment variables:
- **Key:** `CRON_SECRET`
- **Value:** any random string (e.g. `openssl rand -hex 32` in your terminal)

Vercel automatically injects this value into the `Authorization` header for every scheduled cron invocation — you don't have to configure anything else. Your `vercel.json` already has the schedule wired up (`"schedule": "0 16 * * *"`) so the only missing piece is the guard.

**Why this matters:** A cron route that anyone can call isn't really a cron — it's just an API route on a timer. The secret verification is what makes it *exclusively* a scheduled job. This same pattern (header-based bearer token) is how most scheduled job platforms authenticate: Railway, Render, and EasyCron all work the same way.
