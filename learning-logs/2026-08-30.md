Today's focus: **Heartbeats**

You have a heartbeat API route that pings your webhook endpoint and reports status. Right now nothing reads that status — it only writes to logs. The natural next step is to surface it in the UI with a React hook that polls the endpoint client-side, so you can see the health of your app at a glance.

**Step 1 — create `app/hooks/useHeartbeat.ts`:**

```ts
"use client";

import { useState, useEffect, useCallback } from "react";

type HeartbeatStatus = "ok" | "degraded" | "loading" | "error";

interface HeartbeatResult {
  status: HeartbeatStatus;
  timestamp: string | null;
  checks: Record<string, string> | null;
}

export function useHeartbeat(intervalMs = 30_000): HeartbeatResult {
  const [result, setResult] = useState<HeartbeatResult>({
    status: "loading",
    timestamp: null,
    checks: null,
  });

  const poll = useCallback(async () => {
    try {
      const res = await fetch("/api/cron/heartbeat");
      if (!res.ok) throw new Error(`HTTP ${res.status}`);
      const data = await res.json();
      setResult({
        status: data.status ?? "error",
        timestamp: data.timestamp ?? null,
        checks: data.checks ?? null,
      });
    } catch {
      setResult((prev) => ({ ...prev, status: "error", timestamp: null }));
    }
  }, []);

  useEffect(() => {
    poll(); // fire immediately on mount
    const id = setInterval(poll, intervalMs);
    return () => clearInterval(id); // clean up on unmount
  }, [poll, intervalMs]);

  return result;
}
```

const STATUS_COLORS: Record<string, string> = {

**Three concepts to lock in:**

1. **Why `useCallback` wraps `poll`?** The `poll` function is declared inside the component's render scope. Without `useCallback`, a new function reference is created on every render — and since it's listed in `useEffect`'s dependency array, that would cause the effect to re-run (and the interval to reset) on every render. `useCallback` memoizes it so the reference only changes when its own deps change.

2. **Why `clearInterval` in the cleanup?** React's `useEffect` cleanup runs when the component unmounts *and* before the effect re-runs due to dependency changes. Without `clearInterval`, navigating away from the page leaves the interval running — it will keep fetching `/api/cron/heartbeat` indefinitely and try to call `setResult` on an unmounted component. This is the canonical React resource-cleanup pattern.

3. **What's the difference between client-side polling and a server cron?** Your Vercel cron calls the heartbeat route on a fixed schedule from the *server side* — it runs whether or not anyone has the page open. The `useHeartbeat` hook polls from the *client side* — it only runs while a browser tab has the page open. Both are valid heartbeat patterns; they answer different questions: "is the server healthy?" (cron) vs. "is the app reachable from a browser right now?" (hook).
