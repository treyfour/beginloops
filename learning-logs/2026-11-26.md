Today's focus: **Webhooks — verifying that incoming events actually came from the service that claims to have sent them**

Right now your webhook route receives any POST request. In production, services like GitHub and Stripe sign every webhook payload with a secret key. If you skip verification, anyone can send fake events to your endpoint.

Here's how to verify a GitHub webhook signature (the same pattern applies to Stripe with minor changes):

```ts
// app/api/webhooks/route.ts
import { createHmac, timingSafeEqual } from "crypto";
import { NextRequest, NextResponse } from "next/server";

const WEBHOOK_SECRET = process.env.WEBHOOK_SECRET ?? "";

function verifySignature(payload: string, signature: string): boolean {
  const expected = createHmac("sha256", WEBHOOK_SECRET)
    .update(payload)
    .digest("hex");
  const expectedBuf = Buffer.from(`sha256=${expected}`, "utf8");
  const sigBuf = Buffer.from(signature, "utf8");
  if (expectedBuf.length !== sigBuf.length) return false;
  return timingSafeEqual(expectedBuf, sigBuf);
}

export async function POST(req: NextRequest) {
  const signature = req.headers.get("x-hub-signature-256") ?? "";
  const rawBody = await req.text();

  if (!verifySignature(rawBody, signature)) {
    return NextResponse.json({ error: "Invalid signature" }, { status: 401 });
  }

  const payload = JSON.parse(rawBody);
  console.log("Verified webhook payload:", payload);

  return NextResponse.json({ received: true });
}
```

Then add `WEBHOOK_SECRET` to your `.env.local`:
```
WEBHOOK_SECRET=your_secret_from_github_or_stripe
```

**Why this matters:** `timingSafeEqual` is not optional — a naive string comparison (`expected === signature`) leaks timing information that lets attackers forge signatures byte by byte. The two-step pattern (hash the raw body, compare with timing-safe equality) is the same approach used by every serious webhook consumer. Once you understand it here, you'll recognize it instantly in any service's docs.
