Today's focus: **Crons — multiple jobs and CRON_SECRET auth**

Your `vercel.json` already has one cron. Vercel supports up to 20 crons per project, and each is just an entry in the `crons` array pointing at a different route. A "daily summary" job that runs once a day (at midnight UTC) alongside the more frequent heartbeat is the perfect second cron — it shows how you orchestrate different intervals for different purposes.

**Update `vercel.json`:**

```json
{
  "crons": [
    {
      "path": "/api/cron/heartbeat",
      "schedule": "0 16 * * *"
    },
    {
      "path": "/api/cron/daily-summary",
      "schedule": "0 0 * * *"
    }
  ]
}
```

**Create `app/api/cron/daily-summary/route.ts`:**

```ts
export async function GET(req: Request) {
  // Vercel secures cron routes with a Bearer token in production — always verify it
  const authHeader = req.headers.get("authorization");
  if (authHeader !== `Bearer ${process.env.CRON_SECRET}`) {
    return Response.json({ error: "Unauthorized" }, { status: 401 });
  }

  const summary = {
    timestamp: new Date().toISOString(),
    message: "Daily summary cron ran successfully",
    // TODO: query your DB or logs to report on today's heartbeat history
  };

  console.log("Daily summary:", summary);
  return Response.json(summary);
}
```

Add `CRON_SECRET=your-secret-here` to `.env.local` and your Vercel environment variables. Vercel automatically injects this as a `Bearer` token when it invokes your route — it's how you prevent any random HTTP client from triggering your cron manually.

**Why this matters:** Most real apps need multiple crons at different rates — a heartbeat every few minutes, a rollup every hour, a cleanup every night. The pattern here (one `vercel.json` entry + one route handler per job) scales to all of them. The `CRON_SECRET` check is Vercel's recommended cron security approach, directly analogous to the HMAC signature verification you added to the webhook endpoint — protect your input, always.
