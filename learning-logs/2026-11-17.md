Today's focus: **Crons — running multiple jobs on different schedules**

Right now `vercel.json` has one cron. Add a second one:

```json
{
  "crons": [
    {
      "path": "/api/cron/heartbeat",
      "schedule": "0 8 * * *"
    },
    {
      "path": "/api/cron/weekly-summary",
      "schedule": "0 9 * * 1"
    }
  ]
}
```

Then create `app/api/cron/weekly-summary/route.ts`:

```ts
import { NextResponse } from "next/server";

export async function GET(req: Request) {
  // Guard: only Vercel's cron runner can call this
  const secret = req.headers.get("authorization");
  if (secret !== `Bearer ${process.env.CRON_SECRET}`) {
    return NextResponse.json({ error: "unauthorized" }, { status: 401 });
  }

  const summary = {
    week: new Date().toISOString().slice(0, 10),
    message: "Weekly summary cron fired",
  };

  console.log("[weekly-summary]", JSON.stringify(summary));
  return NextResponse.json(summary);
}
```

**Why two crons?** Real apps rarely have just one scheduled job — you might send a daily digest *and* a weekly rollup. Learning to express both in `vercel.json` and route them to separate handlers shows you how to keep cron logic modular.

**What is `0 9 * * 1`?** That's a standard cron expression: minute=0, hour=9, any day-of-month, any month, day-of-week=1 (Monday). The [crontab.guru](https://crontab.guru) site is the fastest way to read or write these without memorizing the field order.
