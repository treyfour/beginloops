Today's focus: **Webhooks security — verifying the sender with a shared secret**

Right now your `/api/webhooks` endpoint accepts `POST` requests from *anyone*. In production that means anyone who discovers the URL can send fake events. GitHub signs every webhook request with an HMAC-SHA256 digest of the payload — you set a secret when registering the webhook, and GitHub attaches the signature as the `X-Hub-Signature-256` header. Your handler verifies the signature before trusting the body.

**Add this to `app/api/webhooks/route.ts`:**

```ts
import { NextRequest, NextResponse } from "next/server";
import crypto from "crypto";

// Add this helper above the POST handler
async function verifyGitHubSignature(
  req: NextRequest,
  rawBody: string
): Promise<boolean> {
  const secret = process.env.GITHUB_WEBHOOK_SECRET;
  if (!secret) {
    // In dev, skip verification if no secret is set
    console.warn("[webhooks] GITHUB_WEBHOOK_SECRET not set — skipping verification");
    return true;
  }

  const signature = req.headers.get("x-hub-signature-256");
  if (!signature) return false;

  const expected = "sha256=" + crypto
    .createHmac("sha256", secret)
    .update(rawBody)
    .digest("hex");

  // Use timingSafeEqual to prevent timing attacks
  const sigBuf = Buffer.from(signature);
  const expBuf = Buffer.from(expected);
  if (sigBuf.length !== expBuf.length) return false;

  return crypto.timingSafeEqual(sigBuf, expBuf);
}

// Update your POST handler to read the raw body first
export async function POST(req: NextRequest) {
  const rawBody = await req.text(); // read as text to preserve exact bytes for HMAC
  const isValid = await verifyGitHubSignature(req, rawBody);

  if (!isValid) {
    console.warn("[webhooks] Invalid signature — rejecting request");
    return NextResponse.json({ error: "Unauthorized" }, { status: 401 });
  }

  const body = JSON.parse(rawBody); // now safe to parse
  const event = req.headers.get("x-github-event") ?? "unknown";

  // ... rest of your existing handler unchanged
}
```

**Three concepts to lock in:**

1. **HMAC — Hash-based Message Authentication Code** — not encryption, but a fingerprint only someone with the shared secret can produce. GitHub runs `HMAC-SHA256(payload, secret)` before sending; you run the same computation on arrival. If the digests match, the request came from GitHub (or someone with your secret).

2. **`crypto.timingSafeEqual`** — a constant-time comparison that prevents *timing attacks*. A regular `===` returns early on the first differing byte; an attacker probing thousands of requests can measure that tiny difference to guess the correct signature byte-by-byte. `timingSafeEqual` always takes the same amount of time.

3. **Raw body matters** — the HMAC is computed over the *exact bytes* GitHub sends. Parsing the body as JSON first (`req.json()`) can normalize whitespace or key order, producing a different byte sequence and a signature mismatch. Always read `req.text()` first, verify, then `JSON.parse`.
