The backend heartbeat has been sitting idle with nobody consuming it. A custom React hook is the right abstraction to bridge the server's health data into your UI — and it's a perfect introduction to how hooks encapsulate stateful logic.

**Step 1 — create `hooks/useHeartbeat.ts`:**

```ts
import { useEffect, useRef, useState } from "react";

export type HeartbeatStatus = "ok" | "degraded" | "loading" | "error";

export interface HeartbeatResult {
  status: HeartbeatStatus;
  timestamp: string | null;
  checks: Record<string, string>;
}

/**
 * Polls /api/cron/heartbeat every `intervalMs` milliseconds.
 * Returns the latest status, timestamp, and per-check breakdown.
 *
 * @param intervalMs - how often to poll, default 30 000 (30 s)
 */
export function useHeartbeat(intervalMs = 30_000): HeartbeatResult {
  const [result, setResult] = useState<HeartbeatResult>({
    status: "loading",
    timestamp: null,
    checks: {},
  });
  const timerRef = useRef<ReturnType<typeof setTimeout> | null>(null);

  async function poll() {
    try {
      const res = await fetch("/api/cron/heartbeat");
      if (!res.ok) throw new Error(`HTTP ${res.status}`);
      const data = await res.json();
      setResult({
        status: data.status ?? "error",
        timestamp: data.timestamp ?? null,
        checks: data.checks ?? {},
      });
    } catch {
      setResult((prev) => ({ ...prev, status: "error" }));
    }
    // schedule the next poll
    timerRef.current = setTimeout(poll, intervalMs);
  }

  useEffect(() => {
    poll();                                  // fire immediately on mount
    return () => {
      if (timerRef.current) clearTimeout(timerRef.current);
    };
    // eslint-disable-next-line react-hooks/exhaustive-deps
  }, [intervalMs]);

  return result;
}
```

**Step 2 — use it on the homepage in `app/page.tsx`:**

```tsx
import { useHeartbeat } from "@/hooks/useHeartbeat";

const STATUS_COLORS: Record<string, string> = {
  ok:      "bg-green-500",
  degraded:"bg-yellow-500",
  error:   "bg-red-500",
  loading: "bg-gray-400 animate-pulse",
};

export default function Home() {
  const { status, timestamp } = useHeartbeat(30_000);

  return (
    <main className="p-8">
      <h1 className="text-2xl font-bold mb-4">beginloops</h1>

      {/* Health badge */}
      <div className="flex items-center gap-2">
        <span className={`inline-block h-3 w-3 rounded-full ${STATUS_COLORS[status]}`} />
        <span className="text-sm text-gray-600 dark:text-gray-400">
          {status === "loading" ? "checking…" : `heartbeat: ${status}`}
        </span>
        {timestamp && (
          <span className="text-xs text-gray-400 ml-2">
            {new Date(timestamp).toLocaleTimeString()}
          </span>
        )}
      </div>
    </main>
  );
}
```

**Three concepts to lock in:**

1. **Why `useRef` for the timer instead of a plain variable?**
   A plain variable inside the hook would be re-created on every render, losing the previous timer ID. `useRef` gives you a mutable container whose value persists across renders without causing a re-render when you write to it — perfect for holding a timer handle you need to cancel on unmount.

2. **Why `setTimeout` in a loop instead of `setInterval`?**
   `setInterval` fires on a fixed wall-clock cadence regardless of how long each fetch takes. If a fetch takes 5 s and your interval is 10 s, the next request starts 5 s after the previous response — not ideal. Scheduling the *next* `setTimeout` after each response completes ensures a consistent *gap* between polls. It also prevents queue build-up if the server is slow.

3. **Why is the cleanup function in `useEffect` important?**
   When the component unmounts (e.g., the user navigates away), the `clearTimeout` in the cleanup cancels the pending timer. Without it, the hook would keep fetching and calling `setResult` on an unmounted component, causing a React memory-leak warning and potentially surfacing stale data on remount.
