**Add GitHub webhook signature verification to `app/api/webhooks/route.ts` — this is the security step that makes your webhook production-safe and teaches you how HMAC-SHA256 works in practice.**

Right now anyone can POST to your webhook and it will run. GitHub signs every request with a secret you set in their dashboard; your handler should reject anything that doesn't have a valid signature.

**Step 1 — Add a `GITHUB_WEBHOOK_SECRET` environment variable in `.env.local`:**

```
GITHUB_WEBHOOK_SECRET=your-secret-here
```

Pick any random string (e.g. `openssl rand -hex 32`) and set the same value in your GitHub repo webhook settings under **Settings → Webhooks → Secret**.

**Step 2 — Add a `verifySignature` helper at the top of `app/api/webhooks/route.ts`:**

```ts
async function verifySignature(req: NextRequest, body: string): Promise<boolean> {
  const sig = req.headers.get("x-hub-signature-256");
  const secret = process.env.GITHUB_WEBHOOK_SECRET;
  if (!sig || !secret) return false;

  const encoder = new TextEncoder();
  const key = await crypto.subtle.importKey(
    "raw",
    encoder.encode(secret),
    { name: "HMAC", hash: "SHA-256" },
    false,
    ["sign"]
  );
  const mac = await crypto.subtle.sign("HMAC", key, encoder.encode(body));
  const expected = "sha256=" + Array.from(new Uint8Array(mac))
    .map((b) => b.toString(16).padStart(2, "0"))
    .join("");

  return sig === expected;
}
```

**Why this matters:** Signature verification is the pattern used by every serious webhook provider (GitHub, Stripe, Twilio). It proves the payload came from the claimed sender and wasn't tampered with in transit. `crypto.subtle` is the Web Crypto API — it's available in Next.js Edge and Node runtimes without any imports, so this is zero-dependency security.
