Today's focus: **Hooks (custom React hooks — connecting your API layer to the UI)**

You've built two API endpoints (`/api/webhooks` and `/api/cron/heartbeat`) but nothing in the UI consumes them yet. A custom hook is the idiomatic Next.js/React way to bridge that gap: it owns the fetch, the interval, and the cleanup — the component just reads the result.

**Step 1 — Create `app/hooks/useCronStatus.ts`:**

```ts
"use client";

import { useState, useEffect } from "react";

interface HeartbeatResult {
  status: "ok" | "degraded" | null;
  timestamp: string | null;
  loading: boolean;
  error: string | null;
}

export function useCronStatus(intervalMs = 30_000): HeartbeatResult {
  const [state, setState] = useState<HeartbeatResult>({
    status: null,
    timestamp: null,
    loading: true,
    error: null,
  });

  useEffect(() => {
    let cancelled = false;

    async function poll() {
      try {
        const res = await fetch("/api/cron/heartbeat");
        if (!res.ok) throw new Error(`HTTP ${res.status}`);
        const data = await res.json();
        if (!cancelled) {
          setState({ status: data.status, timestamp: data.timestamp, loading: false, error: null });
        }
      } catch (err) {
        if (!cancelled) {
          setState(prev => ({ ...prev, loading: false, error: String(err) }));
        }
      }
    }

    poll(); // run immediately on mount
    const id = setInterval(poll, intervalMs); // then every N ms

    return () => {
      cancelled = true;
      clearInterval(id); // cleanup — this is why hooks beat raw useEffect calls
    };
  }, [intervalMs]);

  return state;
}
```

**Step 2 — Use it in `app/page.tsx`:**

```tsx
"use client";

import { useCronStatus } from "./hooks/useCronStatus";

export default function Home() {
  const { status, timestamp, loading, error } = useCronStatus();

  return (
    <main className="p-8">
      <h1 className="text-2xl font-bold mb-4">beginloops</h1>

      <section className="border rounded p-4 max-w-sm">
        <h2 className="font-semibold mb-2">System Health</h2>
        {loading && <p className="text-gray-500">Checking…</p>}
        {error && <p className="text-red-500">Error: {error}</p>}
        {status && (
          <>
            <p>
              Status:{" "}
              <span className={status === "ok" ? "text-green-600" : "text-red-500"}>
                {status}
              </span>
            </p>
            <p className="text-sm text-gray-400 mt-1">
              Last checked: {timestamp ? new Date(timestamp).toLocaleTimeString() : "—"}
            </p>
          </>
        )}
      </section>
    </main>
  );
}
```

**Three concepts to lock in:**

1. **The cleanup function in `useEffect` is not optional.** If you skip `clearInterval(id)`, the old interval keeps firing after the component unmounts — or worse, after a hot-reload in development — and you get stale state updates and memory leaks. The `cancelled` flag guards against `setState` on an unmounted component inside an already-running `poll()` call.

2. **Custom hooks are just functions that call other hooks.** There is no magic API — `useCronStatus` is a plain TypeScript function. What makes it a hook is that it calls `useState` and `useEffect` internally, which means React can track its state per component instance. You can call `useCronStatus(5000)` in two different components and each gets its own independent polling interval.

3. **Your hook is the contract, not the implementation.** If you later replace the `fetch` inside the hook with a WebSocket subscription or a Server-Sent Events stream, `page.tsx` never changes — it still just reads `{ status, timestamp, loading }`. That's the design leverage hooks give you.
