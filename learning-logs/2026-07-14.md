## Suggested next step
Protect the cron endpoint with **Vercel's `CRON_SECRET`** — the built-in mechanism that ensures only Vercel's scheduler (and you, locally) can trigger your cron routes.

Vercel automatically injects an `Authorization: Bearer <CRON_SECRET>` header on every cron invocation. Add this guard at the top of `app/api/cron/heartbeat/route.ts`:

```ts
export async function GET(req: Request) {
  const authHeader = req.headers.get("authorization");
  if (authHeader !== `Bearer ${process.env.CRON_SECRET}`) {
    return new Response("Unauthorized", { status: 401 });
  }

  // ... rest of handler unchanged
}
```

Then set `CRON_SECRET` in your Vercel project settings (Settings → Environment Variables). For local testing, add it to `.env.local` and pass the header manually:

```bash
curl -H "Authorization: Bearer your-secret-here" http://localhost:3000/api/cron/heartbeat
```

**Why this matters:** Without this check, anyone who discovers your `/api/cron/heartbeat` URL can trigger it at will — hammering your downstream services, inflating logs, or abusing rate-limited resources. `CRON_SECRET` is the cron equivalent of webhook signature verification: a shared secret that proves the caller is who they claim to be. It's also the pattern Vercel's own docs recommend, so you'll see it in every production Next.js + Vercel cron setup.
