Today's focus: **Webhook security — verifying signatures with the Web Crypto API**

Every real webhook service signs its payloads with a shared secret and a hash. You verify the signature before trusting the payload. Without this step, anyone who discovers your endpoint URL can POST fake events. Here's how to add it.

**Step 1 — set your secret in `.env.local`:**

```bash
WEBHOOK_SECRET=your-secret-here
```

On Vercel, add it under Project → Settings → Environment Variables.

**Step 2 — create a reusable verifier (`app/lib/verifyWebhookSignature.ts`):**

```ts
/**
 * Verifies an HMAC-SHA256 webhook signature using the Web Crypto API.
 * Works in Next.js Edge Runtime and Node.js serverless functions alike.
 *
 * @param payload  The raw request body (string — must be the exact bytes sent)
 * @param signature  The hex digest from the sender's header (e.g. "sha256=abc123…")
 * @param secret  Your shared secret (from env)
 * @returns true if the signature is valid
 */
export async function verifyWebhookSignature(
  payload: string,
  signature: string,
  secret: string
): Promise<boolean> {
  const encoder = new TextEncoder();

  // Import the secret as a CryptoKey
  const key = await crypto.subtle.importKey(
    "raw",
    encoder.encode(secret),
    { name: "HMAC", hash: "SHA-256" },
    false,
    ["sign"]
  );

  // Compute our expected signature
  const signatureBuffer = await crypto.subtle.sign(
    "HMAC",
    key,
    encoder.encode(payload)
  );

  // Convert to hex string
  const expectedHex = Array.from(new Uint8Array(signatureBuffer))
    .map((b) => b.toString(16).padStart(2, "0"))
    .join("");

  // The sender typically sends "sha256=<hex>", strip the prefix if present
  const receivedHex = signature.replace(/^sha256=/, "");

  // Constant-time comparison prevents timing attacks
  if (expectedHex.length !== receivedHex.length) return false;
  let diff = 0;
  for (let i = 0; i < expectedHex.length; i++) {
    diff |= expectedHex.charCodeAt(i) ^ receivedHex.charCodeAt(i);
  }
  return diff === 0;
}
```

**Step 3 — update `app/api/webhooks/route.ts` to verify before processing:**

```ts
import { verifyWebhookSignature } from "@/app/lib/verifyWebhookSignature";

const MAX_EVENTS = 20;
export const webhookLog: Array<{ id: string; ts: string; payload: unknown }> = [];

export async function POST(req: Request) {
  const secret = process.env.WEBHOOK_SECRET;
  if (!secret) {
    console.error("[webhook] WEBHOOK_SECRET not set");
    return new Response("Server misconfiguration", { status: 500 });
  }

  // Read the raw body ONCE — you can't read a Request body twice
  const rawBody = await req.text();

  // GitHub uses X-Hub-Signature-256; Stripe uses Stripe-Signature (different format)
  const signature =
    req.headers.get("x-hub-signature-256") ??
    req.headers.get("x-webhook-signature") ??
    "";

  if (!signature) {
    return new Response("Missing signature header", { status: 401 });
  }

  const valid = await verifyWebhookSignature(rawBody, signature, secret);
  if (!valid) {
    console.warn("[webhook] invalid signature — rejecting request");
    return new Response("Invalid signature", { status: 401 });
  }

  const payload = JSON.parse(rawBody);
  webhookLog.unshift({
    id: crypto.randomUUID(),
    ts: new Date().toISOString(),
    payload,
  });
  if (webhookLog.length > MAX_EVENTS) webhookLog.length = MAX_EVENTS;
  console.log("[webhook] verified and logged", payload);
  return Response.json({ ok: true });
}
```

**Test it locally with a correctly signed request:**

```bash
# Set your secret
export SECRET="your-secret-here"

# Build a payload and sign it
PAYLOAD='{"event":"push","ref":"refs/heads/main"}'
SIG=$(echo -n "$PAYLOAD" | openssl dgst -sha256 -hmac "$SECRET" | awk '{print "sha256="$2}')

# Send with the correct signature — should return {"ok":true}
curl -X POST http://localhost:3000/api/webhooks \
  -H "Content-Type: application/json" \
  -H "X-Hub-Signature-256: $SIG" \
  -d "$PAYLOAD"

# Send without a signature — should return 401
curl -X POST http://localhost:3000/api/webhooks \
  -H "Content-Type: application/json" \
  -d "$PAYLOAD"
```

**Three concepts to lock in:**

1. **Why `req.text()` instead of `req.json()`** — you must read the raw bytes before parsing, because `JSON.stringify(JSON.parse(body))` can reorder keys and change whitespace, which breaks the signature. The sender signed the exact byte sequence they sent; you must hash that same sequence. Always read the body as `text()` before hashing, then `JSON.parse()` it yourself.

2. **Constant-time comparison prevents timing attacks** — a naive `===` string check leaks information: if it short-circuits on the first mismatched character, an attacker can measure response times to guess the correct signature one byte at a time. XOR-comparing all bytes and checking the combined result afterward eliminates that leak.

3. **`crypto.subtle` is the right tool for edge environments** — Node's built-in `crypto.createHmac` works in a regular serverless function, but Next.js Edge Runtime (and Cloudflare Workers) don't have it. `crypto.subtle` is part of the Web Crypto API, available everywhere. Building the habit of using it makes your code portable across runtimes from the start.
