Today's focus: **Hooks**

Right now your heartbeat check fires server-side and the result disappears into logs. A custom hook turns that data into reactive UI state. This is the pattern every production dashboard uses.

**Step 1 — Create `app/hooks/useHeartbeat.ts`:**

```ts
"use client";

import { useEffect, useState } from "react";

interface HeartbeatStatus {
  status: "ok" | "degraded" | "loading";
  timestamp: string | null;
  checks: { webhookEndpoint: "ok" | "unreachable" } | null;
}

export function useHeartbeat(intervalMs = 30_000): HeartbeatStatus {
  const [result, setResult] = useState<HeartbeatStatus>({
    status: "loading",
    timestamp: null,
    checks: null,
  });

  useEffect(() => {
    async function poll() {
      try {
        const res = await fetch("/api/cron/heartbeat");
        const data = await res.json();
        setResult(data);
      } catch {
        setResult({ status: "degraded", timestamp: null, checks: null });
      }
    }

    poll();
    const id = setInterval(poll, intervalMs);
    return () => clearInterval(id);
  }, [intervalMs]);

  return result;
}
```

**Step 2 — Wire it into `app/page.tsx`:**

```tsx
"use client";

import { useHeartbeat } from "./hooks/useHeartbeat";

export default function Home() {
  const { status, timestamp } = useHeartbeat();

  return (
    <main>
      <p>Webhook endpoint: <strong>{status}</strong></p>
      {timestamp && <p>Last checked: {new Date(timestamp).toLocaleTimeString()}</p>}
    </main>
  );
}
```

**Why this matters:** Custom hooks are the idiomatic way to encapsulate any stateful or side-effectful logic in React — polling, subscriptions, WebSockets, localStorage sync. The `useEffect` + `setInterval` + cleanup pattern here is the exact same shape you'd use for a live order feed, a deployment status indicator, or a chat unread count. Learn this shape once and it transfers everywhere.
