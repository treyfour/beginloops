Today's focus: **Custom React hooks — turning a raw `fetch` into a reusable, reactive data source**

Your heartbeat endpoint already returns structured JSON like `{ status: "ok", timestamp: "...", checks: { webhookEndpoint: "ok" } }`. Right now nothing in the UI consumes it. A custom hook is the idiomatic Next.js/React way to bridge a backend endpoint and a UI component.

**Step 1 — create `app/hooks/useHeartbeat.ts`:**

```ts
"use client";

import { useState, useEffect, useCallback } from "react";

interface HeartbeatPayload {
  status: "ok" | "degraded";
  timestamp: string;
  checks: {
    webhookEndpoint: "ok" | "unreachable";
  };
}

interface HeartbeatState {
  data: HeartbeatPayload | null;
  loading: boolean;
  error: string | null;
  refresh: () => void;
}

/**
 * Polls the /api/cron/heartbeat endpoint on a given interval.
 * Returns the latest payload, a loading flag, any error, and a manual refresh fn.
 */
export function useHeartbeat(intervalMs = 30_000): HeartbeatState {
  const [data, setData] = useState<HeartbeatPayload | null>(null);
  const [loading, setLoading] = useState(true);
  const [error, setError] = useState<string | null>(null);

  const fetchHeartbeat = useCallback(async () => {
    setLoading(true);
    setError(null);
    try {
      const res = await fetch("/api/cron/heartbeat", {
        // In local dev you won't have CRON_SECRET middleware — add a note here
        headers: {},
      });
      if (!res.ok) throw new Error(`${res.status} ${res.statusText}`);
      const json: HeartbeatPayload = await res.json();
      setData(json);
    } catch (err) {
      setError(err instanceof Error ? err.message : "Unknown error");
    } finally {
      setLoading(false);
    }
  }, []);

  useEffect(() => {
    fetchHeartbeat(); // fetch immediately on mount

    const timer = setInterval(fetchHeartbeat, intervalMs);
    return () => clearInterval(timer); // cleanup on unmount
  }, [fetchHeartbeat, intervalMs]);

  return { data, loading, error, refresh: fetchHeartbeat };
}
```

**Step 2 — use it in `app/page.tsx`:**

```tsx
"use client";

import { useHeartbeat } from "./hooks/useHeartbeat";

export default function Home() {
  const { data, loading, error } = useHeartbeat(15_000); // poll every 15s

  return (
    <main className="p-8">
      <h1 className="text-2xl font-bold mb-4">beginloops status</h1>
      {loading && <p className="text-gray-400">Checking heartbeat…</p>}
      {error && <p className="text-red-500">Error: {error}</p>}
      {data && (
        <div className="rounded border p-4 space-y-2">
          <p>
            Status:{" "}
            <span className={data.status === "ok" ? "text-green-500" : "text-yellow-400"}>
              {data.status}
            </span>
          </p>
          <p>Webhook endpoint: {data.checks.webhookEndpoint}</p>
          <p className="text-sm text-gray-500">
            Last checked: {new Date(data.timestamp).toLocaleTimeString()}
          </p>
        </div>
      )}
    </main>
  );
}
```

**Three concepts to lock in:**

1. **`useEffect` + `setInterval` = polling** — `useEffect` with a cleanup function is the standard pattern for subscribing to any time-based or external data source. The `return () => clearInterval(timer)` line prevents memory leaks when the component unmounts. This same pattern works for WebSocket subscriptions, event listeners, and timers.

2. **`useCallback` prevents infinite loops** — if `fetchHeartbeat` were defined inline inside `useEffect`, it would be a new function reference on every render, triggering the effect on every render. Wrapping it in `useCallback` with a stable `[]` dependency array makes it a stable reference.

3. **Separation of concerns: hook vs component** — the hook owns *how* to fetch and *when* to re-fetch; the component owns *how* to display the result. This split makes both testable independently — you can test the hook with a mocked `fetch`, and test the component with a mocked hook return value.
