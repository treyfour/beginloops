Today's focus: **Webhooks — securing your endpoint with signature verification**

Your webhook handler currently accepts any POST request without checking whether it actually came from GitHub. GitHub signs every payload with your webhook secret and sends the signature in the `x-hub-signature-256` header. Add a `verifySignature` helper that rejects requests with invalid signatures:

```ts
import { createHmac, timingSafeEqual } from "crypto";

async function verifySignature(req: NextRequest, body: string): Promise<boolean> {
  const secret = process.env.GITHUB_WEBHOOK_SECRET;
  if (!secret) return false;

  const sig = req.headers.get("x-hub-signature-256");
  if (!sig || !sig.startsWith("sha256=")) return false;

  const expected = "sha256=" + createHmac("sha256", secret).update(body).digest("hex");
  const sigBuf = Buffer.from(sig);
  const expBuf = Buffer.from(expected);

  return sigBuf.length === expBuf.length && timingSafeEqual(sigBuf, expBuf);
}
```

Then update the `POST` handler to read the raw body text first and reject early if the signature fails:

```ts
export async function POST(req: NextRequest) {
  const rawBody = await req.text();
  const valid = await verifySignature(req, rawBody);
  if (!valid) return NextResponse.json({ error: "Unauthorized" }, { status: 401 });

  const event = req.headers.get("x-github-event") ?? "unknown";
  const body = JSON.parse(rawBody);
  // ... rest of handler unchanged
}
```

Set `GITHUB_WEBHOOK_SECRET` in your Vercel project's environment variables (and in a local `.env.local`). In your GitHub repo's webhook settings, paste the same string into the "Secret" field.

**Why this matters:** An unsigned endpoint can be spoofed by anyone who knows its URL — forged payloads could trigger builds, send false alerts, or flood your logs. `timingSafeEqual` is critical here: a naive `===` comparison leaks timing information that lets an attacker brute-force the secret byte-by-byte. This pattern is the same one used by Stripe, Twilio, and every major webhook provider.
