**Protect your Vercel cron endpoint from unauthorized calls by verifying the `CRON_SECRET` header in `app/api/cron/heartbeat/route.ts`.**

Today's focus: **Crons — authorization guard for Vercel cron jobs**

Vercel automatically injects an `Authorization: Bearer <CRON_SECRET>` header on every scheduled cron invocation. Without this check, anyone who discovers your cron URL can trigger it on demand — wasting compute, skewing logs, or abusing downstream rate limits.

Update `app/api/cron/heartbeat/route.ts`:

```ts
import { NextRequest, NextResponse } from "next/server";

export async function GET(req: NextRequest) {
  const auth = req.headers.get("authorization");
  if (auth !== `Bearer ${process.env.CRON_SECRET}`) {
    return NextResponse.json({ error: "Unauthorized" }, { status: 401 });
  }

  const base = process.env.VERCEL_URL
    ? `https://${process.env.VERCEL_URL}`
    : "http://localhost:3000";

  let webhookStatus: "ok" | "unreachable" = "unreachable";
  try {
    const res = await fetch(`${base}/api/webhooks`, {
      method: "POST",
      headers: { "Content-Type": "application/json", "x-github-event": "ping" },
      body: JSON.stringify({ zen: "heartbeat probe" }),
    });
    webhookStatus = res.ok ? "ok" : "unreachable";
  } catch {
    webhookStatus = "unreachable";
  }

  const payload = {
    status: webhookStatus === "ok" ? "ok" : "degraded",
    timestamp: new Date().toISOString(),
    checks: { webhookEndpoint: webhookStatus },
  };

  console.log("[heartbeat]", JSON.stringify(payload));
  return NextResponse.json(payload);
}
```

Then add `CRON_SECRET=<a-random-string>` to `.env.local` and to your Vercel project's environment variables (Settings → Environment Variables). Vercel sets this secret automatically on deployed projects — it's documented in their [Cron Jobs security guide](https://vercel.com/docs/cron-jobs/manage-cron-jobs#securing-cron-jobs).

**Why this matters:** Cron endpoints are HTTP routes like any other — `vercel.json` just tells Vercel to call them on a schedule. That means they're publicly reachable URLs. The `CRON_SECRET` check is a one-line guard that mirrors exactly what you did (or will do) with HMAC on the webhook side: verify the caller is who they claim to be before doing any work. This pattern — authenticate before processing — is the foundation of secure backend design.
