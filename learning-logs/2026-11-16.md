Today's focus: **Webhooks — verifying the sender with HMAC signatures**

GitHub computes `HMAC-SHA256(secret, raw_body)` and sends the result in the `X-Hub-Signature-256` header. Your handler needs to recompute the same hash and compare — only proceed if they match.

Add this to `app/api/webhooks/route.ts`:

```ts
import { createHmac, timingSafeEqual } from "crypto";

async function verifySignature(req: NextRequest, rawBody: string): Promise<boolean> {
  const sig = req.headers.get("x-hub-signature-256");
  const secret = process.env.GITHUB_WEBHOOK_SECRET;
  if (!sig || !secret) return false;

  const expected = "sha256=" + createHmac("sha256", secret).update(rawBody).digest("hex");
  return timingSafeEqual(Buffer.from(sig), Buffer.from(expected));
}

export async function POST(req: NextRequest) {
  const rawBody = await req.text();                    // read as text, not json
  if (!(await verifySignature(req, rawBody))) {
    return NextResponse.json({ error: "invalid signature" }, { status: 401 });
  }
  const body = JSON.parse(rawBody);                    // parse after verification
  // ... rest of handler unchanged
}
```

Then in GitHub → Repo Settings → Webhooks → your webhook, set the **Secret** field to a random value (generate with `openssl rand -hex 32`) and add the same value to Vercel as `GITHUB_WEBHOOK_SECRET`.

**Why `timingSafeEqual`?** A plain `===` string compare leaks timing information — an attacker can probe character-by-character. `timingSafeEqual` always takes the same time regardless of where the strings diverge, closing that side channel.

**Why `req.text()` instead of `req.json()`?** The HMAC is computed over the exact raw bytes GitHub sent. Parsing to JSON and re-serializing can change whitespace or key order, breaking the hash. Always hash the raw body.
