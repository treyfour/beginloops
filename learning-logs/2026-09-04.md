Today's focus: **Webhook event routing — handling multiple event types in a single endpoint**

Real webhook providers (GitHub, Stripe, Clerk, Resend) send many different event types to the same URL. Right now your webhook route logs everything the same way. The next step is to branch on event type so each event gets its own logic.

**Update `app/api/webhooks/route.ts`:**

```ts
import { NextRequest, NextResponse } from "next/server";

// --- typed event shapes ---
interface PingEvent   { type: "ping";   message: string }
interface OrderEvent  { type: "order";  orderId: string; total: number }
interface UserEvent   { type: "user";   userId: string; action: "created" | "deleted" }

type WebhookEvent = PingEvent | OrderEvent | UserEvent;

// --- per-event handlers ---
function handlePing(event: PingEvent) {
  console.log("[webhook] ping received:", event.message);
}

function handleOrder(event: OrderEvent) {
  console.log(`[webhook] order ${event.orderId} — $${event.total}`);
  // TODO: update DB, send confirmation email, etc.
}

function handleUser(event: UserEvent) {
  console.log(`[webhook] user ${event.userId} was ${event.action}`);
  // TODO: provision or de-provision resources
}

// --- router ---
export async function POST(req: NextRequest) {
  let body: WebhookEvent;

  try {
    body = await req.json();
  } catch {
    return NextResponse.json({ error: "Invalid JSON" }, { status: 400 });
  }

  switch (body.type) {
    case "ping":
      handlePing(body);
      break;
    case "order":
      handleOrder(body);
      break;
    case "user":
      handleUser(body);
      break;
    default:
      console.warn("[webhook] unknown event type:", (body as { type?: string }).type);
      return NextResponse.json({ error: "Unknown event type" }, { status: 422 });
  }

  return NextResponse.json({ received: true });
}
```

**Three concepts to lock in:**

1. **One URL, many event types** — webhook providers expect a single endpoint URL. The payload's `type` field (or a custom header like `x-github-event`) is how you tell events apart. The `switch` statement is the standard dispatch pattern.

2. **TypeScript discriminated unions** — `WebhookEvent = PingEvent | OrderEvent | UserEvent` is a discriminated union. After the `switch (body.type)` check, TypeScript *narrows* the type automatically — inside `case "order":`, it knows `body` is `OrderEvent`. No casting needed.

3. **422 vs 400** — return `400 Bad Request` when the payload is malformed (not valid JSON), and `422 Unprocessable Entity` when the JSON is valid but semantically wrong (unknown event type). Many webhook retry systems treat 4xx differently than 5xx — only 5xx triggers a retry, so always return 2xx or 422 for events you intentionally skip.
