Today's focus: **Hooks (custom React hooks that consume your backend)**

You already have a `/api/cron/heartbeat` endpoint that returns a status payload. The natural next move is to make the frontend consume it. A custom React hook wraps `fetch` + `useEffect` + `useState` into a single reusable unit that any component can call:

```ts
// lib/useHeartbeat.ts
"use client";

import { useEffect, useState } from "react";

interface HeartbeatStatus {
  status: "ok" | "degraded" | "loading" | "error";
  timestamp: string | null;
  checks: { webhookEndpoint: "ok" | "unreachable" } | null;
}

export function useHeartbeat(intervalMs = 30_000): HeartbeatStatus {
  const [state, setState] = useState<HeartbeatStatus>({
    status: "loading",
    timestamp: null,
    checks: null,
  });

  useEffect(() => {
    let cancelled = false;

    async function poll() {
      try {
        const res = await fetch("/api/cron/heartbeat");
        if (cancelled) return;

        if (!res.ok) {
          setState({ status: "error", timestamp: new Date().toISOString(), checks: null });
          return;
        }

        const data = await res.json();
        if (!cancelled) setState(data);
      } catch {
        if (!cancelled) setState({ status: "error", timestamp: new Date().toISOString(), checks: null });
      }
    }

    poll();                                   // fire immediately on mount
    const id = setInterval(poll, intervalMs); // then on each interval

    return () => {
      cancelled = true;   // stop any in-flight fetch from updating state
      clearInterval(id);  // tear down the interval on unmount
    };
  }, [intervalMs]);

  return state;
}
```

Then consume it in your homepage:

```tsx
// app/page.tsx  (add to the top of the file)
"use client";
import { useHeartbeat } from "@/lib/useHeartbeat";

// Inside your component:
const { status, timestamp } = useHeartbeat(15_000); // poll every 15 seconds

// In JSX:
<p>System: {status} · last checked {timestamp ? new Date(timestamp).toLocaleTimeString() : "…"}</p>
```

**Three concepts to lock in:**

1. **`useEffect` + cleanup = safe polling.** The returned cleanup function (`() => { cancelled = true; clearInterval(id); }`) is what React calls when the component unmounts. Without it, the interval keeps firing after the component is gone and tries to call `setState` on an unmounted component — a classic memory-leak pattern. The `cancelled` flag is equally important: it prevents a slow in-flight fetch from updating state after unmount even when the interval is cleared.

2. **Custom hooks are just functions that call other hooks.** There's no magic API — `useHeartbeat` is a plain function that happens to use `useState` and `useEffect`. React's only rule: hook functions must start with `use`. Everything else (the polling logic, the shape of what you return) is up to you. This makes them the primary unit of reuse in React — the same thing `useRouter`, `useParams`, and `useSWR` are built from.

3. **`"use client"` is required for hooks.** Next.js App Router runs components on the server by default. `useState` and `useEffect` are browser APIs — they don't exist on the server. Adding `"use client"` at the top of the file tells Next.js to bundle it for the browser. Any component that imports a client hook also becomes a client component (Next.js enforces this transitively).
