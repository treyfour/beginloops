**Add HMAC-SHA256 signature verification to `app/api/webhooks/route.ts` — this is the standard way real webhook consumers verify that a request genuinely came from the sender (GitHub, Stripe, etc.) and not an attacker replaying your endpoint.**

Update `app/api/webhooks/route.ts`:

```ts
import { NextRequest, NextResponse } from "next/server";
import { createHmac, timingSafeEqual } from "crypto";

const SECRET = process.env.WEBHOOK_SECRET ?? "";

export async function POST(req: NextRequest) {
  const rawBody = await req.text();
  const signature = req.headers.get("x-hub-signature-256") ?? "";

  // Compute the expected signature
  const expected = "sha256=" + createHmac("sha256", SECRET).update(rawBody).digest("hex");

  // timingSafeEqual prevents timing attacks
  const sigBuf = Buffer.from(signature);
  const expBuf = Buffer.from(expected);
  if (sigBuf.length !== expBuf.length || !timingSafeEqual(sigBuf, expBuf)) {
    return NextResponse.json({ error: "Invalid signature" }, { status: 401 });
  }

  const payload = JSON.parse(rawBody);
  console.log("Verified webhook payload:", payload);
  return NextResponse.json({ received: true });
}
```

Then add `WEBHOOK_SECRET=your-secret` to `.env.local`.

**Why this matters:** Without signature verification, anyone who discovers your webhook URL can send fake events — triggering deploys, charges, or state changes. `timingSafeEqual` is critical: a plain `===` comparison leaks timing information that lets an attacker brute-force the secret one byte at a time. This is the exact pattern GitHub and Stripe document in their webhook security guides and is considered table-stakes for production webhook handlers.
