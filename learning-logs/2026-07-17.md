## Suggested next step
Add **webhook delivery deduplication** to `app/api/webhooks/route.ts` using the `x-github-delivery` header. GitHub attaches a unique UUID to every webhook delivery and re-sends that *same* UUID on retries — so you can use it to safely ignore duplicate deliveries.

Add this near the top of the file (module-level, outside the handler):

```ts
// Simple in-memory dedup window — survives the request lifecycle but resets on cold start
const seenDeliveries = new Map<string, number>();
const DEDUP_TTL_MS = 5 * 60 * 1000; // 5 minutes

function isDuplicate(deliveryId: string): boolean {
  const now = Date.now();
  // Evict stale entries so the Map doesn't grow unbounded
  for (const [id, ts] of seenDeliveries) {
    if (now - ts > DEDUP_TTL_MS) seenDeliveries.delete(id);
  }
  if (seenDeliveries.has(deliveryId)) return true;
  seenDeliveries.set(deliveryId, now);
  return false;
}
```

Then guard your `POST` handler with it:

```ts
export async function POST(req: NextRequest) {
  const deliveryId = req.headers.get("x-github-delivery") ?? "";
  if (deliveryId && isDuplicate(deliveryId)) {
    return NextResponse.json({ skipped: true, reason: "duplicate delivery" }, { status: 200 });
  }

  const event = req.headers.get("x-github-event") ?? "unknown";
  // ... rest of existing handler unchanged
}
```

**Why this matters:** GitHub retries a webhook three times over several hours whenever it gets a non-2xx response (network glitch, cold start timeout, deploy restart). Without deduplication, a single push event can trigger your handler 2–4 times — which is fine for logging but catastrophic for anything side-effectful (sending a Slack message, creating a database record, kicking off a build). Idempotency is the first thing production webhook systems add after getting the happy path working. The `x-github-delivery` header is the idempotency key GitHub hands you for free — use it. Note that `Map` resets on cold start, so a production system would use Redis or a database; but the `Map` pattern teaches the concept cleanly and is correct for the scope of this project.
