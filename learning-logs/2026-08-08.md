Today's focus: **Hooks (custom `useEffect` polling)**

The heartbeat endpoint already exists. The missing piece is the front-end hook that calls it on a timer and gives the UI live state. This is the canonical heartbeat pattern in React: a `useEffect` that starts a `setInterval`, returns a cleanup function to clear it on unmount, and stores the latest response in local state.

**Step 1 — Create `hooks/useHeartbeat.ts`:**

```ts
"use client";
import { useEffect, useState } from "react";

interface HeartbeatStatus {
  ok: boolean;
  lastChecked: Date | null;
  latencyMs: number | null;
  error: string | null;
}

export function useHeartbeat(intervalMs = 30_000): HeartbeatStatus {
  const [status, setStatus] = useState<HeartbeatStatus>({
    ok: false,
    lastChecked: null,
    latencyMs: null,
    error: null,
  });

  useEffect(() => {
    async function ping() {
      const start = performance.now();
      try {
        const res = await fetch("/api/cron/heartbeat");
        const latencyMs = Math.round(performance.now() - start);
        setStatus({ ok: res.ok, lastChecked: new Date(), latencyMs, error: null });
      } catch (err) {
        setStatus((prev) => ({
          ...prev,
          ok: false,
          error: err instanceof Error ? err.message : "fetch failed",
        }));
      }
    }

    ping(); // fire immediately on mount
    const id = setInterval(ping, intervalMs);
    return () => clearInterval(id); // cleanup on unmount — this is the critical part
  }, [intervalMs]);

  return status;
}
```

**Step 2 — Wire it into `app/page.tsx`:**

```tsx
"use client";
import { useHeartbeat } from "@/hooks/useHeartbeat";

export default function Home() {
  const { ok, lastChecked, latencyMs, error } = useHeartbeat(30_000);

  return (
    <main className="flex flex-col items-center justify-center min-h-screen gap-4">
      <h1 className="text-2xl font-semibold">beginloops</h1>

      {/* Live heartbeat badge */}
      <div className={`flex items-center gap-2 rounded-full px-4 py-1.5 text-sm font-medium ${
        ok ? "bg-green-100 text-green-800" : "bg-red-100 text-red-800"
      }`}>
        <span className={`h-2 w-2 rounded-full ${ok ? "bg-green-500 animate-pulse" : "bg-red-500"}`} />
        {ok ? `Alive · ${latencyMs}ms` : error ?? "Checking…"}
      </div>

      {lastChecked && (
        <p className="text-xs text-zinc-400">
          Last checked: {lastChecked.toLocaleTimeString()}
        </p>
      )}
    </main>
  );
}
```

**Why the cleanup function matters:**

Without `return () => clearInterval(id)`, the interval keeps firing after the component unmounts — a classic React memory leak. Every navigation away from the page would start a new orphaned interval, multiplying polling requests. The cleanup function is React's way of saying "when this component is gone, undo the side effect."

**Why `"use client"` at the top:**

`useEffect` and `useState` are client-side React hooks. In Next.js App Router, all components are Server Components by default, which run only on the server and cannot use browser APIs or stateful hooks. The `"use client"` directive tells the bundler to include this file in the client bundle and allow hooks. The heartbeat endpoint (`/api/cron/heartbeat`) is still a Server Component route — only the *page* polling it needs to be a Client Component.
