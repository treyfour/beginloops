Today's focus: **Webhooks — validating the `x-hub-signature-256` header so only your real GitHub webhook can trigger your handler**

GitHub signs every webhook payload with HMAC-SHA256 using your webhook secret. Add this check at the top of your `POST` handler:

```ts
// app/api/webhooks/route.ts
import { NextRequest, NextResponse } from "next/server";
import { createHmac, timingSafeEqual } from "crypto";

async function verifySignature(req: NextRequest, rawBody: Buffer): Promise<boolean> {
  const secret = process.env.GITHUB_WEBHOOK_SECRET;
  if (!secret) return true; // skip check in local dev when not set

  const sig = req.headers.get("x-hub-signature-256");
  if (!sig) return false;

  const expected = "sha256=" + createHmac("sha256", secret).update(rawBody).digest("hex");
  return timingSafeEqual(Buffer.from(sig), Buffer.from(expected));
}

export async function POST(req: NextRequest) {
  const rawBody = Buffer.from(await req.arrayBuffer());

  if (!(await verifySignature(req, rawBody))) {
    return NextResponse.json({ error: "Invalid signature" }, { status: 401 });
```

Then set `GITHUB_WEBHOOK_SECRET` in your Vercel environment variables to match the secret you entered when you created the GitHub webhook.

**Why `timingSafeEqual`?** A naive `===` string comparison leaks timing information — an attacker can probe how many bytes match. `timingSafeEqual` always takes constant time regardless of where the strings first differ, closing that side-channel.

**Why this matters:** Without signature verification, anyone who discovers your webhook URL can POST crafted payloads and trigger your handler with fake push events. Signature verification is the foundational security primitive for webhooks — the same pattern applies to Stripe, Slack, and every other service that sends event callbacks.
