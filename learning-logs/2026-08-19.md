Today's focus: **Webhooks (making your receiver trustworthy)**

Right now, `app/api/webhooks/route.ts` accepts any POST request and treats it as a real GitHub event. A bad actor could POST a fake `push` event pointing to malicious files and your route would log it as truth. GitHub prevents this by signing every payload with a shared secret — your job is to verify that signature before trusting anything.

Here's the verified route:

```ts
// app/api/webhooks/route.ts
import { NextRequest, NextResponse } from "next/server";

// --- HMAC verification helper ---
async function verifyGitHubSignature(
  rawBody: string,
  signatureHeader: string | null,
  secret: string
): Promise<boolean> {
  if (!signatureHeader?.startsWith("sha256=")) return false;
  const receivedHex = signatureHeader.slice(7); // strip "sha256="

  // Derive the expected signature using Web Crypto (available in Edge and Node)
  const key = await crypto.subtle.importKey(
    "raw",
    new TextEncoder().encode(secret),
    { name: "HMAC", hash: "SHA-256" },
    false,
    ["sign"]
  );
  const sig = await crypto.subtle.sign("HMAC", key, new TextEncoder().encode(rawBody));
  const expectedHex = Array.from(new Uint8Array(sig))
    .map((b) => b.toString(16).padStart(2, "0"))
    .join("");

  // Constant-time comparison to prevent timing attacks
  if (receivedHex.length !== expectedHex.length) return false;
  let mismatch = 0;
  for (let i = 0; i < expectedHex.length; i++) {
    mismatch |= receivedHex.charCodeAt(i) ^ expectedHex.charCodeAt(i);
  }
  return mismatch === 0;
}

// ... keep your existing PushEvent interface and parsePushEvent function unchanged ...

export async function POST(req: NextRequest) {
  const secret = process.env.GITHUB_WEBHOOK_SECRET;

  if (secret) {
    const rawBody = await req.text(); // read once as text for signature check
    const signature = req.headers.get("x-hub-signature-256");
    const valid = await verifyGitHubSignature(rawBody, signature, secret);
    if (!valid) {
      console.warn("[webhook] rejected — invalid signature");
      return NextResponse.json({ error: "Invalid signature" }, { status: 401 });
    }
    // Re-parse the body we already consumed as text
    const body = JSON.parse(rawBody);
    return handleEvent(req, body);
  }

  // No secret set — log a warning but allow through (useful in local dev)
  console.warn("[webhook] GITHUB_WEBHOOK_SECRET not set — skipping verification");
  const body = await req.json();
  return handleEvent(req, body);
}

function handleEvent(req: NextRequest, body: unknown) {
  const event = req.headers.get("x-github-event") ?? "unknown";
  // ... your existing push/fallback logic here ...
  return NextResponse.json({ event, received: true });
}
```

**Three concepts to lock in:**

1. **`x-hub-signature-256` is GitHub's signature header.** GitHub computes `HMAC-SHA256(secret, rawBody)` and puts the hex result in `X-Hub-Signature-256: sha256=<hex>`. You recompute the same thing and compare — if they match, the payload came from GitHub and wasn't tampered with.

2. **You must read the raw body as text before parsing it.** Once you call `req.json()`, the body stream is consumed and you can't re-read it. Call `req.text()` first, verify the signature against the raw string, then call `JSON.parse()` on it.

3. **Constant-time comparison prevents timing attacks.** A naive `===` comparison short-circuits on the first mismatch — an attacker can measure nanosecond differences to brute-force a valid signature one character at a time. XOR-ing every byte and OR-ing the results takes the same time regardless of where the mismatch is.
