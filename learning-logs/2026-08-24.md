Today's focus: **Crons (securing scheduled routes)**

Right now, anyone who knows your URL can GET `/api/cron/heartbeat` and trigger the probe at will. Vercel solves this by automatically sending an `Authorization: Bearer <CRON_SECRET>` header on every cron invocation — your handler just needs to check for it.

Here is the updated `app/api/cron/heartbeat/route.ts`:

```ts
import { NextRequest, NextResponse } from "next/server";

export async function GET(req: NextRequest) {
  // ── Verify this request came from Vercel's scheduler ─────────────────────
  const cronSecret = process.env.CRON_SECRET;
  if (cronSecret) {
    const auth = req.headers.get("authorization");
    if (auth !== `Bearer ${cronSecret}`) {
      console.warn("[heartbeat] rejected: missing or invalid CRON_SECRET");
      return NextResponse.json({ error: "unauthorized" }, { status: 401 });
    }
  }

  // ── Health probe ──────────────────────────────────────────────────────────
  const base = process.env.VERCEL_URL
    ? `https://${process.env.VERCEL_URL}`
    : "http://localhost:3000";

  let webhookStatus: "ok" | "unreachable" = "unreachable";
  try {
    const res = await fetch(`${base}/api/webhooks`, {
      method: "POST",
      headers: { "Content-Type": "application/json", "x-github-event": "ping" },
      body: JSON.stringify({ zen: "heartbeat probe" }),
    });
    webhookStatus = res.ok ? "ok" : "unreachable";
  } catch {
    webhookStatus = "unreachable";
  }

  const payload = {
    status: webhookStatus === "ok" ? "ok" : "degraded",
    timestamp: new Date().toISOString(),
    checks: { webhookEndpoint: webhookStatus },
  };

  console.log("[heartbeat]", JSON.stringify(payload));
  return NextResponse.json(payload);
}
```

**To wire it up:**

1. Generate a secret: `openssl rand -hex 32`
2. Add it to Vercel: Settings → Environment Variables → `CRON_SECRET`
3. Vercel automatically reads `CRON_SECRET` and sends it as `Authorization: Bearer …` on every cron call — no extra config needed

**Three concepts to lock in:**

1. **Why `CRON_SECRET` and not a token in the URL?** Vercel's own docs recommend the env-var pattern because query-string tokens appear in server logs and browser history. The `Authorization` header is stripped from logs by Vercel's edge network.

2. **Skip the check in local dev.** The `if (cronSecret)` guard means the route stays fully callable with a plain `curl` when `CRON_SECRET` isn't set locally — you don't need to fake the header during development.

3. **The pattern mirrors what you did for webhooks.** Webhooks use HMAC to verify the *sender* (GitHub); crons use a shared bearer token to verify the *caller* (Vercel). Both are the same idea — prove you're who you say you are before we run anything — just adapted to what each service sends.

**Test locally:**

```bash
# No CRON_SECRET set → probe runs freely (good for dev)
curl http://localhost:3000/api/cron/heartbeat

# Once CRON_SECRET is set, the unauthenticated call is rejected:
CRON_SECRET=mysecret curl http://localhost:3000/api/cron/heartbeat
# → {"error":"unauthorized"} 401

# Authenticated call succeeds:
CRON_SECRET=mysecret curl -H "Authorization: Bearer mysecret" \
  http://localhost:3000/api/cron/heartbeat
# → {"status":"ok","timestamp":"…","checks":{"webhookEndpoint":"ok"}}
```
