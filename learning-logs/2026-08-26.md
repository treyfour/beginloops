Today's focus: **Heartbeats**

Right now your heartbeat does this:

```
Heartbeat → POST /api/webhooks → "endpoint is reachable" ✓
```

That's a *reachability* check, not a *liveness* check. You won't know if GitHub stopped sending events three days ago — the heartbeat would still report "ok". The fix is a module-level timestamp variable in the webhook route that records the last real POST, then surfaced through the heartbeat response.

**Step 1 — add a tracker to `app/api/webhooks/route.ts`:**

```ts
// Add near the top of the file (module-level — persists across requests within one serverless instance)
let lastRealPingAt: string | null = null;

export async function POST(req: NextRequest) {
  const event = req.headers.get("x-github-event") ?? "unknown";

  // Only stamp "real" events — ignore the heartbeat's own probe
  if (event !== "ping" || (event === "ping" && req.headers.get("x-heartbeat-probe") !== "1")) {
    lastRealPingAt = new Date().toISOString();
  }

  // …rest of existing handler unchanged…
}

// New: expose the tracker to other route modules
export function getLastRealPingAt() {
  return lastRealPingAt;
}
```

**Step 2 — import it in `app/api/cron/heartbeat/route.ts`:**

```ts
import { getLastRealPingAt } from "@/app/api/webhooks/route";

// Inside your GET handler, replace the payload with:
const payload = {
  status: webhookStatus === "ok" ? "ok" : "degraded",
  timestamp: new Date().toISOString(),
  checks: {
    webhookEndpoint: webhookStatus,
    lastRealEventAt: getLastRealPingAt() ?? "never",
  },
};
```

**Three concepts to lock in:**

1. **Reachability vs. liveness.** "Can I reach the endpoint?" and "Is the endpoint actually doing its job?" are different questions. A liveness check needs evidence of real work — a timestamp, a counter, a queue depth — not just an HTTP 200.

2. **Module-level state in serverless.** Next.js route files are Node modules: top-level variables survive across requests *within the same warm serverless instance*. This is intentional for lightweight caching. The catch: a fresh cold-start resets them, so `lastRealPingAt` may be `null` even after real events — always handle `null` gracefully.

3. **Exporting from a route file.** A `route.ts` file is a regular TypeScript module; you can export helper functions alongside your HTTP handlers. This is how the two endpoints share state without a database.
