Today's focus: **Hooks (custom React hooks — bridging backend monitoring to the UI)**

The heartbeat endpoint is already running server-side, but its results only exist in logs. A custom hook pulls that data into the browser so you can see at a glance whether the webhook pipeline is alive. This is the standard "reactive polling" pattern in React and the right entry point to custom hooks — the logic is simple enough to trace end-to-end.

**Step 1 — Create the hook file:**

```ts
// hooks/useHeartbeat.ts
"use client";

import { useEffect, useState } from "react";

type HeartbeatStatus = "loading" | "ok" | "degraded" | "error";

interface HeartbeatData {
  status: "ok" | "degraded";
  timestamp: string;
  checks: {
    webhookEndpoint: "ok" | "unreachable";
    webhookLatencyMs?: number | null;
  };
}

export function useHeartbeat(intervalMs = 30_000) {
  const [status, setStatus] = useState<HeartbeatStatus>("loading");
  const [data, setData] = useState<HeartbeatData | null>(null);
  const [lastChecked, setLastChecked] = useState<Date | null>(null);

  useEffect(() => {
    let cancelled = false;

    async function poll() {
      try {
        const res = await fetch("/api/cron/heartbeat");
        if (cancelled) return;
        if (!res.ok) { setStatus("error"); return; }
        const json: HeartbeatData = await res.json();
        setData(json);
        setStatus(json.status === "ok" ? "ok" : "degraded");
        setLastChecked(new Date());
      } catch {
        if (!cancelled) setStatus("error");
      }
    }

    poll(); // fire immediately on mount
    const id = setInterval(poll, intervalMs);
    return () => { cancelled = true; clearInterval(id); };
  }, [intervalMs]);

  return { status, data, lastChecked };
}
```

**Three concepts to internalize:**

1. **`useEffect` cleanup is non-optional for intervals.** Without `clearInterval` in the cleanup return, the old interval keeps firing after the component unmounts or `intervalMs` changes — causing "setState on unmounted component" warnings in dev and memory leaks in production. The `cancelled` flag handles a subtler race: a fetch that resolves *after* cleanup would otherwise call `setStatus` on a dead component.

2. **Custom hooks are just functions that call React hooks.** There's no special API — the rules are: name starts with `use`, only called from React components or other hooks, no hook calls inside conditionals. Everything else is plain JavaScript. `useHeartbeat` is just a function that happens to own some `useState` slots and a `useEffect` side effect.

3. **Polling vs. push — and when to upgrade.** Polling on an interval is simple and works everywhere, but it wastes a request every 30 seconds even when nothing changes. The next evolution is replacing the interval with a Server-Sent Events (SSE) stream from the heartbeat route: the server pushes a message only when status *changes*, and the hook listens with `EventSource`. You'll tackle SSE when you circle back to webhooks.
