Today's focus: **Heartbeats — the dead man's switch**

Your cron already self-probes the webhook endpoint and logs the result. The missing piece is *external visibility*: right now, if the cron silently stops running (a bad deploy, a misconfigured schedule, a Vercel billing hiccup), nobody knows. A heartbeat ping fixes that.

Add this to `app/api/cron/heartbeat/route.ts` just before the final `return`:

```ts
// Ping external monitor so it knows the cron is still alive
const pingUrl = process.env.HEALTHCHECK_PING_URL;
if (pingUrl) {
  try {
    await fetch(pingUrl, { method: "GET" });
  } catch {
    console.warn("[heartbeat] failed to ping external monitor");
  }
}
```

Then set `HEALTHCHECK_PING_URL` in your Vercel environment variables to the unique URL you get from [healthchecks.io](https://healthchecks.io) (free tier, no credit card). Configure the check period to match your cron schedule (`0 16 * * *` = daily at 16:00 UTC) plus a grace window of ~10 minutes.

**Why this matters:** The heartbeat pattern is a *dead man's switch* — a signal that says "I'm still running." It inverts normal monitoring: instead of a monitor polling your service, *your service* pings the monitor. If the ping stops arriving, the monitor alerts you. This is how production systems detect silent failures in background jobs, crons, and queue workers — failures that never throw an error, they just… stop.

> **Real-world use:** Stripe, GitHub, and every major CI platform use this pattern internally for their own scheduled jobs. Once you understand it, you'll spot it everywhere.
