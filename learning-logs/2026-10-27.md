Today's focus: **Hooks — building a custom React hook wired to real API data**

Your heartbeat endpoint already returns live server status. A custom hook is the cleanest way to bring that data into your UI without scattering `fetch` calls across components. Here's how to build it:

```ts
// app/hooks/useHeartbeat.ts
"use client";
import { useEffect, useState } from "react";

type HeartbeatStatus = "ok" | "degraded" | "loading" | "error";

interface HeartbeatResult {
  status: HeartbeatStatus;
  timestamp: string | null;
}

export function useHeartbeat(intervalMs = 30_000): HeartbeatResult {
  const [result, setResult] = useState<HeartbeatResult>({
    status: "loading",
    timestamp: null,
  });

  useEffect(() => {
    async function poll() {
      try {
        const res = await fetch("/api/cron/heartbeat");
        const data = await res.json();
        setResult({ status: data.status, timestamp: data.timestamp });
      } catch {
        setResult({ status: "error", timestamp: null });
      }
    }

    poll(); // run immediately on mount
    const id = setInterval(poll, intervalMs);
    return () => clearInterval(id); // cleanup on unmount
  }, [intervalMs]);

  return result;
}
```

Then use it in `app/page.tsx`:

```tsx
// app/page.tsx
import { useHeartbeat } from "./hooks/useHeartbeat";

export default function Home() {
  const { status, timestamp } = useHeartbeat();

  return (
    <main>
      <p>Server: <strong>{status}</strong></p>
      {timestamp && <p>Last checked: {new Date(timestamp).toLocaleTimeString()}</p>}
    </main>
  );
}
```

The key insight: **a custom hook is just a function that calls built-in hooks (`useEffect`, `useState`) and returns data your component needs.** The `useEffect` cleanup (`return () => clearInterval(id)`) is critical — without it, the interval keeps running even after the component unmounts, causing memory leaks. This pattern (fetch on mount → poll on interval → cleanup on unmount) is the foundation of every real-time UI widget.
