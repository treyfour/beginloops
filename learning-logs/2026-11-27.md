Today's focus: **Crons — making a cron job's output visible and queryable**

Your heartbeat cron at `/api/cron/heartbeat` already runs and logs a JSON payload:

```json
{ "status": "ok", "timestamp": "2026-11-27T16:00:00.000Z", "checks": { "webhookEndpoint": "ok" } }
```

But it only logs to the console — no one can query it. Add a status endpoint that holds the last result in memory (in production you'd swap this for Redis or Vercel KV, but for learning, in-memory is exactly right):

```ts
// app/api/status/route.ts
import { NextResponse } from "next/server";

interface HeartbeatResult {
  status: "ok" | "degraded";
  timestamp: string;
  checks: { webhookEndpoint: "ok" | "unreachable" };
}

let lastHeartbeat: HeartbeatResult | null = null;

export function setLastHeartbeat(result: HeartbeatResult) {
  lastHeartbeat = result;
}

export async function GET() {
  return NextResponse.json(
    lastHeartbeat ?? { status: "unknown", timestamp: null, checks: {} }
  );
}
```

Then update `app/api/cron/heartbeat/route.ts` to import `setLastHeartbeat` and call it with the payload before returning. Now any component — including the `useHeartbeat` hook suggested two days ago — can `fetch("/api/status")` and display the live system state.

**Why this matters:** Crons are fire-and-forget by nature — they run, do work, and exit. Making their output queryable via a plain GET endpoint is the standard pattern for cron-driven health dashboards, status pages, and monitoring UIs. Once you internalize this shape (cron writes → endpoint exposes → component reads), you'll recognize it in Uptime Robot, Vercel Cron logs, Render health checks, and every status page you've ever visited.
