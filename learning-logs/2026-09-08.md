Today's focus: **Webhooks — signature verification**

Right now your webhook endpoint accepts any POST request from anywhere on the internet. Real webhook senders like GitHub and Stripe sign every payload with a secret key using HMAC-SHA256. Verifying that signature before trusting the payload is a one-time, ten-line addition — and it's the difference between a demo and production code.

**Update `app/api/webhooks/route.ts`:**

```ts
import { NextRequest, NextResponse } from "next/server";
import { createHmac, timingSafeEqual } from "crypto";

const WEBHOOK_SECRET = process.env.WEBHOOK_SECRET ?? "";

function verifySignature(body: string, sigHeader: string | null): boolean {
  if (!sigHeader || !WEBHOOK_SECRET) return false;

  // GitHub sends "sha256=<hex>" — strip the prefix
  const [algo, theirHex] = sigHeader.split("=");
  if (algo !== "sha256") return false;

  const ourHmac = createHmac("sha256", WEBHOOK_SECRET)
    .update(body, "utf8")
    .digest("hex");

  // timingSafeEqual prevents timing-based attacks
  const ourBuf = Buffer.from(ourHmac, "hex");
  const theirBuf = Buffer.from(theirHex, "hex");
  if (ourBuf.length !== theirBuf.length) return false;

  return timingSafeEqual(ourBuf, theirBuf);
}

export async function POST(req: NextRequest) {
  const rawBody = await req.text(); // read raw bytes before JSON.parse
  const sig = req.headers.get("x-hub-signature-256");

  if (!verifySignature(rawBody, sig)) {
    return NextResponse.json({ error: "invalid signature" }, { status: 401 });
  }

  const payload = JSON.parse(rawBody);
  console.log("[webhook] verified event:", payload.ref);

  return NextResponse.json({ ok: true });
}
```

**Add `WEBHOOK_SECRET` to your environment:**
1. In Vercel dashboard → Project → Settings → Environment Variables: add `WEBHOOK_SECRET` with a random 32-byte value (run `openssl rand -hex 32` locally to generate one).
2. In your GitHub repo → Settings → Webhooks → your webhook → Secret: paste the same value.

**Three concepts to lock in:**

1. **HMAC-SHA256** — a keyed hash. You and GitHub both know the secret; GitHub hashes the raw payload with it and sends the result in a header. You hash the same raw body with your copy of the secret and compare. If they match, only GitHub (who knows the secret) could have sent it.

2. **`timingSafeEqual`** — a simple `===` comparison of hex strings leaks timing information: an attacker can measure how long the comparison takes to learn how many bytes matched. `timingSafeEqual` always runs in constant time regardless of where the bytes differ, closing that side-channel.

3. **`req.text()` before `JSON.parse`** — HMAC is computed over the exact raw bytes on the wire, whitespace included. If you `req.json()` first, you've already deserialized and re-serialized, which can silently alter the byte sequence. Always read the raw body, verify the signature, then parse.
