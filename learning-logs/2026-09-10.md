Today's focus: **Webhooks — signature verification**

Your webhook endpoint currently accepts any POST request. In production, any script on the internet could hit it. Services like GitHub sign their payloads with a shared secret using HMAC-SHA256 — your handler should verify that signature before doing anything with the data.

**Add this to `app/api/webhooks/route.ts`:**

```ts
import { createHmac, timingSafeEqual } from "crypto";

const WEBHOOK_SECRET = process.env.WEBHOOK_SECRET ?? "";

function verifySignature(body: string, signatureHeader: string | null): boolean {
  if (!signatureHeader) return false;
  const expected = "sha256=" + createHmac("sha256", WEBHOOK_SECRET)
    .update(body)
    .digest("hex");
  // timingSafeEqual prevents timing attacks
  try {
    return timingSafeEqual(Buffer.from(signatureHeader), Buffer.from(expected));
  } catch {
    return false; // buffers were different lengths
  }
}

export async function POST(req: Request) {
  const rawBody = await req.text(); // read as raw text to preserve exact bytes
  const sig = req.headers.get("x-hub-signature-256");

  if (!verifySignature(rawBody, sig)) {
    return Response.json({ error: "Invalid signature" }, { status: 401 });
  }

  const payload = JSON.parse(rawBody);
  console.log("Verified webhook payload:", payload);
  return Response.json({ received: true });
}
```

Add `WEBHOOK_SECRET=your-secret-here` to `.env.local` and to your Vercel environment variables.

**Why this matters:** Without signature verification, your webhook is an open door — anyone can POST fake events and trigger your logic. `timingSafeEqual` is the subtle-but-important detail: a naive `===` string comparison leaks timing information that attackers can use to guess the secret byte-by-byte. This exact pattern is used in production systems handling real financial and deployment events.
