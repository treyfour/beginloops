Today's focus: **Webhooks (security — signature verification)**

Your webhook route currently accepts any POST request. GitHub signs every payload with a shared secret using HMAC-SHA256 and sends the signature in the `x-hub-signature-256` header. Without checking that signature, anyone who discovers your endpoint URL can send fake events — triggering whatever logic you add later (deploys, notifications, etc.). This is the single most important hardening step for any public webhook.

**Step 1 — Add your webhook secret to `.env.local`:**


Set the same value in your GitHub repo → Settings → Webhooks → Secret.

```ts
// app/api/webhooks/route.ts  (replace the top of the file)
import { NextRequest, NextResponse } from "next/server";

async function verifyGitHubSignature(req: NextRequest, rawBody: string): Promise<boolean> {
  const secret = process.env.WEBHOOK_SECRET;
  if (!secret) return false;

  const sigHeader = req.headers.get("x-hub-signature-256");
  if (!sigHeader?.startsWith("sha256=")) return false;
  const theirSig = sigHeader.slice(7); // strip "sha256=" prefix

  // Use the Web Crypto API — available in Next.js Edge/Node runtimes alike
  const encoder = new TextEncoder();
  const key = await crypto.subtle.importKey(
    "raw",
    encoder.encode(secret),
    { name: "HMAC", hash: "SHA-256" },
    false,
    ["sign"]
  );
  const mac = await crypto.subtle.sign("HMAC", key, encoder.encode(rawBody));
  const ourSig = Buffer.from(mac).toString("hex");

  // Timing-safe compare: compare byte-by-byte to avoid timing attacks
  if (ourSig.length !== theirSig.length) return false;
  let mismatch = 0;
  for (let i = 0; i < ourSig.length; i++) {
    mismatch |= ourSig.charCodeAt(i) ^ theirSig.charCodeAt(i);
  }
  return mismatch === 0;
}

export async function POST(req: NextRequest) {
  const rawBody = await req.text(); // read body as text FIRST — json() consumes the stream
  const valid = await verifyGitHubSignature(req, rawBody);

  if (!valid) {
    console.warn("[webhook] rejected — invalid signature");
    return NextResponse.json({ error: "Unauthorized" }, { status: 401 });
  }

}
```

**Three concepts to internalize:**

1. **HMAC (Hash-based Message Authentication Code):** You and GitHub share a secret. GitHub uses it to sign the payload before sending; you re-sign the received payload with the same secret and compare. If the signatures match, the payload hasn't been tampered with and came from someone who knows the secret.

2. **Timing-safe comparison:** A naïve `ourSig === theirSig` leaks information — it returns early on the first mismatched character, so an attacker can measure how long the comparison takes and iteratively reconstruct the correct signature one character at a time. The loop with `|=` always runs to completion regardless of where the mismatch is.

3. **Read body as text, not JSON:** `req.json()` consumes the readable stream. If you call it before `verifyGitHubSignature`, the raw bytes are gone and you can't compute the HMAC (which must be over the exact bytes GitHub sent). Always call `req.text()` first, then `JSON.parse()`.
