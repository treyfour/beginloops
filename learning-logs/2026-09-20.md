Today's focus: **Webhooks — signature verification**

Right now your webhook route accepts any POST request. GitHub signs every payload it sends using a shared secret and the HMAC-SHA256 algorithm; if you don't verify that signature, a bad actor who discovers your URL can send fabricated events and your handler will act on them.

Update `app/api/webhooks/route.ts`:

```ts
import { NextRequest, NextResponse } from "next/server";
import { createHmac, timingSafeEqual } from "crypto";

function verifySignature(payload: string, sigHeader: string | null): boolean {
  const secret = process.env.GITHUB_WEBHOOK_SECRET;
  if (!secret || !sigHeader) return false;

  const expected = "sha256=" + createHmac("sha256", secret).update(payload).digest("hex");
  const expectedBuf = Buffer.from(expected, "utf8");
  const receivedBuf = Buffer.from(sigHeader, "utf8");

  // timingSafeEqual prevents timing attacks; buffers must be the same length
  if (expectedBuf.length !== receivedBuf.length) return false;
  return timingSafeEqual(expectedBuf, receivedBuf);
}

export async function POST(req: NextRequest) {
  const rawBody = await req.text();
  const sig = req.headers.get("x-hub-signature-256");

  if (!verifySignature(rawBody, sig)) {
    return NextResponse.json({ error: "Invalid signature" }, { status: 401 });
  }

  const payload = JSON.parse(rawBody);
  console.log("Verified webhook event:", payload.action ?? "(no action)");
  return NextResponse.json({ received: true });
}
```

Then set `GITHUB_WEBHOOK_SECRET` in your Vercel project settings to match the secret you configured on the GitHub webhook.

**Why this matters:** `timingSafeEqual` is the subtle but critical detail — a naive `===` comparison leaks timing information that an attacker can use to guess the correct signature one byte at a time. This is the same pattern used by every major webhook provider (GitHub, Stripe, Twilio). Once you understand it here, you'll recognize it everywhere. The companion pattern for crons is the `CRON_SECRET` authorization header — you've seen both sides of the same security coin.
